## 桌面捕获 → NVENC 编码 → 文件保存 完整流程

### 一、整体架构

```
[桌面] → DXGI Output Duplication → ScreenCapture
                                           ↓ BGRA (ID3D11Texture2D*)
                                    NvencEncoder
                                           ↓ H.264 ES (vector<uint8_t>)
                                    fwrite → capture_10s.h264
                                           ↓ (可选)
                                    ffplay 回放验证
```

### 二、各环节详细说明

#### 环节 1：桌面捕获（ScreenCapture）

**入口**：`PlayerApp::TestScreenCapture()` 第 306 行

```
ScreenCapture capture;
capture.Init();    // 自动创建 D3D11 设备 + DXGI OutputDuplication
```

- **底层 API**：`IDXGIOutput5::DuplicateOutput1`（优先 NV12）→ 回退 `IDXGIOutput1::DuplicateOutput`
- **gpu_texture_ 格式**：`DXGI_FORMAT_B8G8R8A8_UNORM`（BGRA）
- **输出**：`ID3D11Texture2D*`（GPU 显存，BGRA）
- **频率**：显示器刷新率（60/120/144Hz）

每帧调用：
```cpp
ID3D11Texture2D* tex = nullptr;
capture.CaptureNextFrame(tex);
// tex 是 GPU 显存中的 BGRA 纹理
// 所有权归 ScreenCapture，下次调用前必须使用完毕
```

#### 环节 2：调试——保存第一帧 BGRA 原图（可跳过）

**位置**：`PlayerApp::TestScreenCapture()` 第 332-372 行

```
从 GPU 纹理 → Staging Texture → CPU 回读 → fwrite → debug_frame.bgra
```

用于对比验证：**原图正常**说明 Capture 环节没问题。

ffplay 查看原图：
```
ffplay -f rawvideo -pixel_format bgra -video_size WxH -i debug_frame.bgra
```

#### 环节 3：NVENC 编码（NvencEncoder）

**初始化**（第 308-310 行）：
```cpp
NvencEncoder encoder;
encoder.Init(capture.GetDevice(), capture.Width(), capture.Height(),
             capture.FrameRate(), 10000);    // 10 Mbps
```

**当前编码管线（有 VideoProcessor 版）：**
```
ScreenCapture → CopyResource → bgra_texture_
                                   ↓ VideoProcessorBlt (BGRA→NV12)
                               nv12_texture_
                                   ↓ nvEncMapInputResource
                               NVENC 硬件编码
                                   ↓ nvEncLockBitstream
                               EncodedFrame (H.264 码流)
```

**重构后的编码管线（去掉 VideoProcessor，NVENC VPP 内部转换）：**
```
ScreenCapture → CopyResource → input_texture_ (BGRA)
                                   ↓ nvEncMapInputResource
                               NVENC 硬件编码（内部 VPP: ARGB→NV12）
                                   ↓ nvEncLockBitstream
                               EncodedFrame (H.264 码流)
```

**当前编码参数：**
- 编码格式：H.264（`NV_ENC_CODEC_H264_GUID`）
- 预设：P1（`NV_ENC_PRESET_P1_GUID`，最快，最低延迟）
- 调优目标：超低延迟（`NV_ENC_TUNING_INFO_ULTRA_LOW_LATENCY`）
- 码控：CBR（`NV_ENC_PARAMS_RC_CBR`）
- 码率：10,000 kbps（由 `bitrate_kbps` 参数指定）
- VBV 缓冲：`bitrate_kbps * 1000 / fps`
- GOP：无限（`NVENC_INFINITE_GOPLENGTH`）
- B 帧：0（`frameIntervalP = 1`，`zeroReorderDelay = 1`）
- 参考帧：1（`maxNumRefFrames = 1`，`numRefL0 = NV_ENC_NUM_REF_FRAMES_1`）
- 熵编码：CABAC
- SLICE：4 分片（`sliceMode = 3, sliceModeData = 4`）
- 色彩声明：BT.709 limited range（VUI 参数标记在 H.264 SPS 中）

**输出**：`EncodedFrame` 结构体
```cpp
struct EncodedFrame {
    std::vector<uint8_t> data;    // H.264 码流（PPS/SPS/IDR/SLICE）
    uint64_t frame_index;
    bool     idr;                 // 是否关键帧
};
```

#### 环节 4：保存为 .h264 文件

**位置**：`PlayerApp::TestScreenCapture()` 第 317-319 行、375-385 行

```cpp
FILE* fp_h264 = nullptr;
fopen_s(&fp_h264, "capture_10s.h264", "wb");

// 循环中：
encoder.EncodeFrame(tex, frame_index, force_idr, enc_frame);
fwrite(enc_frame.data.data(), 1, enc_frame.data.size(), fp_h264);
```

- **输出文件**：`capture_10s.h264`
- **格式**：H.264 裸码流（Annex B 格式，含 0x00000001 start code）
- **内容**：SPS → PPS → IDR → P → P → P → ...
- **时长**：10 秒（`total_frames = frame_rate * 10`）
- **不含音轨**、**不含容器封装**（.h264 不是 .mp4）

#### 环节 5：回放验证

**方式 A** — ffplay 直接播放 .h264（最方便）：
```bash
ffplay capture_10s.h264
```

**方式 B** — 对比 BGRA 原图（色彩问题定位）：
```bash
ffplay -f rawvideo -pixel_format bgra -video_size WxH -i debug_frame.bgra
```

如果原图颜色正常、.h264 播放发黄 → 问题在编码环节的色彩转换。

### 三、当前问题定位

```
原图 (debug_frame.bgra) 颜色正常
  ↓
Capture 环节 ✓
  ↓
BGRA → NV12 转换（VideoProcessor，YCbCr_Matrix=1 配置有误）
  ↓   ← 这里出问题（RGB 输入误设 YCbCr_Matrix）
NVENC 编码
  ↓
H.264 输出 → 播放器解码 → 画面发黄
```

**根因**：`InitVideoProcessor()` 中 `input_cs.YCbCr_Matrix = 1`，但输入是 RGB（BGRA），D3D11 规范要求 RGB 输入时必须为 0。驱动行为未定义，实际效果是蓝色分量被错误衰减 → 偏黄。

**重构目标**：去掉 VideoProcessor 中间层，由 NVENC 驱动内部 VPP 单元自动完成 BGRA→NV12 色彩转换。

### 四、缺失环节——封装为 .mp4

目前保存的是裸 H.264 码流（`.h264`），不是标准容器格式。如果需要 `.mp4` 文件，需要用 FFmpeg 的 libavformat 做 mux：

```cpp
// 伪代码：
AVFormatContext* mux_ctx = nullptr;
avformat_alloc_output_context2(&mux_ctx, nullptr, "mp4", "output.mp4");
// 添加 H.264 视频流
AVStream* vs = avformat_new_stream(mux_ctx, nullptr);
vs->codecpar->codec_id = AV_CODEC_ID_H264;
vs->codecpar->codec_type = AVMEDIA_TYPE_VIDEO;
// ... 设置 width/height/bitrate ...
avio_open(&mux_ctx->pb, "output.mp4", AVIO_FLAG_WRITE);
avformat_write_header(mux_ctx, nullptr);

// 每帧：封装为 AVPacket，写入
AVPacket pkt = { .data = enc_frame.data.data(), .size = (int)enc_frame.data.size(),
                 .pts = frame_index, .dts = frame_index, .flags = idr ? AV_PKT_FLAG_KEY : 0 };
av_write_frame(mux_ctx, &pkt);

av_write_trailer(mux_ctx);
```
