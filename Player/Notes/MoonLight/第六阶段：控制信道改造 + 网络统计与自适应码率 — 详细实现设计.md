# 第六阶段：控制信道改造 + 网络统计与自适应码率 — 详细实现设计

> 基于第五阶段代码完成后的精确实现方案。控制信道已支持 JSON 消息，编码器已支持 force_idr。

## 1. 现状分析

### 1.1 第五阶段已奠定的基础

| 能力 | 状态 | 影响第六阶段 |
|------|------|------------|
| 控制信道 JSON 消息（`CONTROL_MSG_MARKER`） | ✅ 已实现 | 直接复用，新增消息类型即可 |
| 客户端 `SendControlMessage()` | ✅ 已实现 | 网络统计上报直接走这个通道 |
| 服务端 `OnControlMessage()` | ✅ 已实现 | 扩展处理 `loss_report` 消息 |
| 客户端丢包检测（`consecutive_lost_frames_`） | ✅ 已实现 | 暴露为丢包率统计 |
| 服务端 `force_next_idr_` | ✅ 已实现 | 自适应下降也可以触发 IDR |
| VideoReceiver FEC 统计 | ✅ 已实现 | 扩展为完整 `NetworkStats` 结构体 |
| IVideoEncoder `force_idr` | ✅ 已实现 | 码率调整走新接口 |

### 1.2 当前缺陷

| 问题 | 影响 |
|------|------|
| 编码器码率在 Init 时写死，无法运行时调整 | WiFi 信号变差时画面卡死，不能自动降码率 |
| 没有 RTT 测量 | 不知道网络质量，自适应无依据 |
| 客户端统计只在日志输出，不发给服务端 | 服务端没办法做自适应决策 |
| TCP 控制信道存在理论上的队头阻塞 | 输入事件和统计上报共用同一条 TCP 连接 |

### 1.3 控制信道方案决策：继续使用 TCP

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 现有 TCP | 零成本，可靠传输，已在用 | 理论 HoL 阻塞 | **选用** |
| 引入 ENet | 可靠/不可靠双通道，无 HoL | ~100KB 库依赖，额外复杂度 | 暂不引入 |

**理由**：控制信道消息量极小（输入 12 字节/条，统计 <100 字节/秒），TCP 的队头阻塞在此场景下是理论问题而非实际问题。ENet 等后续实测发现输入延迟问题时再评估。

## 3. 控制消息统一

### 3.1 消息类型枚举

```cpp
// Common/Network/NetworkStats.h

// 控制消息类型（扩展 Stage 5 的 CONTROL_MSG_MARKER 协议）
enum class ControlMsgType : uint8_t {
    RequestIDR      = 0x01,   // 请求 IDR 帧（Stage 5 已实现，JSON: "request_idr"）
    LossReport      = 0x02,   // 丢包统计上报（客户端→服务端，JSON: "loss_report"）
    Ping            = 0x03,   // RTT 探测（客户端→服务端，二进制: timestamp）
    Pong            = 0x04,   // RTT 响应（服务端→客户端，二进制: timestamp）
    BitrateChange   = 0x05,   // 码率调整通知（服务端→客户端，JSON: "bitrate_change"）
};
```

### 3.2 消息格式

```
控制消息包格式（每种类型统一）：
┌────────┬────────┬──────────┬──────────────────┐
│ Marker │  Type  │ Length(2)│    Payload       │
│ 0xFF   │ 1 byte │ 大端     │ JSON 或 二进制    │
└────────┴────────┴──────────┴──────────────────┘

RequestIDR:  Payload = {"type":"request_idr"}           (JSON)
LossReport:  Payload = {"loss_rate":2.5,"fps":58,...}   (JSON)
Ping:        Payload = 8 字节 timestamp (ms)            (二进制)
Pong:        Payload = 8 字节 timestamp (ms，原样回传)  (二进制)
BitrateChange: Payload = {"new_bitrate":8500}           (JSON)
```

### 3.3 改造现有代码

第五阶段 `SendControlMessage("request_idr")` 只是用 `"type":"request_idr"` 的 JSON。现在统一改为：

```cpp
// 客户端发送
bool InputTransportClient::SendControlMessage(uint8_t msg_type, const uint8_t* payload, int payload_len);

// 服务端接收
void InputTransportServer::ReceiveLoop(SOCKET client_sock)
{
    // 读 0xFF marker + 1 字节 type + 2 字节 len + payload
    // 根据 type 分发到不同回调
    switch (type) {
        case 0x01: OnIdrRequest(); break;
        case 0x02: OnLossReport(payload); break;
        case 0x03: HandlePing(payload); break;   // 立即回 Pong
        case 0x04: HandlePong(payload); break;
        case 0x05: OnBitrateChange(payload); break;
    }
}
```

**兼容性**：旧的 `SendControlMessage(const char* msg_type)` 改为内部调用新接口，不影响第五阶段 IDR 请求。

## 4. RTT 测量

### 4.1 类设计

```cpp
// Client/Core/RttMeasurer.h

class RttMeasurer
{
public:
    // 设置发送 Ping 的回调（通过控制信道发送）
    void SetSendCallback(std::function<void(uint64_t timestamp_ms)> callback);

    // 收到 Pong 时调用（由 InputTransportClient 在收到 Pong 时触发）
    void OnPongReceived(uint64_t sent_timestamp_ms);

    // 获取最新 RTT（毫秒）
    int GetLatestRtt() const { return latest_rtt_ms_; }

    // 开始周期性 Ping（每 2 秒一次）
    void Start();

    // 停止
    void Stop();

private:
    void PingLoop();

    std::function<void(uint64_t)> send_callback_;
    std::atomic<bool> running_{false};
    std::thread ping_thread_;
    std::atomic<int> latest_rtt_ms_{0};
    uint64_t next_ping_id_{0};
};
```

### 4.2 测量流程

```
客户端 RttMeasurer::PingLoop()        服务端 InputTransportServer
─────────────────────────────────    ──────────────────────────
while (running) {
    t0 = now_ms();
    SendPing(t0);          ─────────→  收到 Ping(t0)
                                       立即 SendPong(t0);
    sleep(2s);
}                           ←─────────  收到 Pong(t0)
t1 = now_ms();
rtt = t1 - t0;
latest_rtt_ms_ = rtt;
```

- Ping 周期：2 秒（太频繁浪费带宽，太慢反应迟钝）
- RTT 用最新值，不用滑动平均（快速响应网络变化）
- Ping 超时：1 秒无响应视为丢包

### 4.3 在哪触发

RttMeasurer 由 `FFmpegPlayer` 管理（类似于 `VideoReceiver`），在 `OpenStream` 后启动：

```cpp
// FFmpegPlayer::SetupIdrRequest 改造为 SetupStreamControl
void FFmpegPlayer::SetupStreamControl(InputTransportClient* transport)
{
    // --- 绑定 IDR 请求（Stage 5）---
    video_receiver_->SetIdrRequestCallback([transport]() {
        transport->SendControlMessage(...);  // type=RequestIDR
    });

    // --- 绑定 RTT 测量（Stage 6 新增）---
    rtt_measurer_ = new RttMeasurer();
    rtt_measurer_->SetSendCallback([transport](uint64_t ts) {
        transport->SendControlMessage(ControlMsgType::Ping, &ts, sizeof(ts));
    });
    rtt_measurer_->Start();
}
```

### 6.2 FFmpeg NVENC 运行时调码率

```cpp
// ObsNvencEncoderFast::SetBitrate
bool ObsNvencEncoderFast::SetBitrate(int bitrate_kbps)
{
    if (bitrate_kbps == bitrate_kbps_)
        return true;

    bitrate_kbps_ = bitrate_kbps;

    // FFmpeg NVENC 支持运行时改 bit_rate
    // av_opt_set 在编码过程中调用也是有效的
    int ret = av_opt_set(codec_ctx_->priv_data, "b",
                         std::to_string(bitrate_kbps_ * 1000).c_str(), 0);
    if (ret < 0)
    {
        qDebug() << "[FastEncoder] 运行时改码率失败, ret=" << ret;
        return false;
    }

    // 同时更新 AVCodecContext（有些 FFmpeg 版本需要）
    codec_ctx_->bit_rate = bitrate_kbps_ * 1000;

    qDebug() << "[FastEncoder] 码率已调整为" << bitrate_kbps_ << "kbps";
    return true;
}
```

### 6.3 BitrateController 策略引擎

```cpp
// Server/BitrateController.h

class BitrateController
{
public:
    BitrateController(int initial_kbps, int min_kbps, int max_kbps);

    // 接收到客户端网络统计报告时调用
    // 返回新的目标码率（可能与之前相同）
    int OnStatsReport(const NetworkStats& stats);

    // 获取当前目标码率
    int GetTargetBitrate() const { return target_bitrate_; }

private:
    int min_kbps_;            // 最低码率（如 5000 = 5Mbps）
    int max_kbps_;            // 最高码率（如 50000 = 50Mbps）
    int target_bitrate_;      // 当前目标码率
    int consecutive_high_loss_; // 连续高丢包次数

    std::chrono::steady_clock::time_point last_adjust_time_; // 上次调整时间
    static constexpr int ADJUST_INTERVAL_MS = 2000;          // 调整间隔（防抖）
    static constexpr float HIGH_LOSS_THRESHOLD = 3.0f;       // 高丢包阈值（%）
    static constexpr float LOW_LOSS_THRESHOLD = 0.5f;        // 低丢包阈值（%）
    static constexpr float DECREASE_FACTOR = 0.85f;          // 降码率系数
    static constexpr float INCREASE_FACTOR = 1.05f;          // 升码率系数
};
```

### 6.4 自适应策略

```
收到 loss_report (每秒一次)
  │
  ├── loss_rate > 5% 或 (loss_rate > 3% 且 连续2次)
  │     → target × 0.85, min = 5000
  │     → 通知客户端: {"type":"bitrate_change","bitrate":target}
  │
  ├── loss_rate < 1% 且 RTT < 50ms 且 距上次调整 > 2s
  │     → target × 1.05, max = 50000
  │     → 通知客户端
  │
  └── 其他 → 不调整
```

**关键设计决策**：
- **下降快、上升慢**：丢包时立即 ×0.85，恢复时 ×1.05 缓慢提升（避免抖动）
- **双阈值**：单独一次 3-5% 丢包可能只是瞬时抖动，连续 2 次才触发下降
- **2 秒防抖**：编码器需要 1-2 帧才能生效，避免频繁调整
- **RTT 辅助判断**：高 RTT 即使丢包率低也应降码率（可能是带宽不足的前兆）

### 6.5 集成到 StreamServer::Run()

```cpp
// StreamServer 新增成员
BitrateController* bitrate_ctrl_{nullptr};

// Init 中：
bitrate_ctrl_ = new BitrateController(bitrate_kbps, 5000, 50000);

// OnControlMessage 中新增 loss_report 处理：
input_server_->OnControlMessage = [this](const char* msg_type, const uint8_t* payload, int len)
{
    if (strcmp(msg_type, "request_idr") == 0)
    {
        force_next_idr_.store(true);
    }
    else if (strcmp(msg_type, "loss_report") == 0)
    {
        NetworkStats stats = ParseLossReport(payload, len);
        int new_bitrate = bitrate_ctrl_->OnStatsReport(stats);
        if (new_bitrate != current_bitrate_)
        {
            encoder_->SetBitrate(new_bitrate);
            current_bitrate_ = new_bitrate;

            // 可选：通知客户端码率变化
            SendBitrateChangeNotification(new_bitrate);
        }
    }
};

// Run() 中不变：编码器 SetBitrate 后立即生效，无需额外处理
```

## 7. 控制信道双向通信

### 7.1 服务端 → 客户端消息

当前 `InputTransportServer` 只接收数据，不发送（除了初始化时发 `ServerMonitorInfo`）。新增 `SendToClient()` 方法用于发送 Pong 和 BitrateChange：

```cpp
class InputTransportServer
{
public:
    // 发送消息到当前客户端（非阻塞，失败无影响）

```

### 7.2 客户端接收服务端消息

当前 `InputTransportClient` 只发送，不接收回调（`Connect` 中接收 `ServerMonitorInfo` 是同步的）。新增异步接收回调：

```cpp
class InputTransportClient
{
public:
    // 设置服务端消息回调（在单独线程中调用，通过 send_callback 发回主线程）
    void SetMessageHandler(std::function<void(uint8_t msg_type, const uint8_t* payload, int len)> handler);
};
```

实现：在 `Connect` 后启动一个独立的接收线程，循环 `recv` 解析消息，触发 `handler`。

## 11. 验收标准

| 指标 | 目标 |
|------|------|
| RTT 测量精度 | ±5ms（与 ping 对比） |
| 码率自适应 | 限速后 5 秒内稳定到新码率 |
