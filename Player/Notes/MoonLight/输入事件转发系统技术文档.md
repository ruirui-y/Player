## 1. 整体架构

### 1.1 数据流

```
┌─────────────────────────────────────────────────────────────┐
│                        客户端 (Client)                        │
│                                                             │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐   │
│  │ InputCollector│───▶│InputTransport│───▶│  TCP Socket│   │
│  │  (Raw Input  │    │   (Client)   │    │   port 47989 │   │
│  │  + 键盘钩子)  │    │              │    │              │   │
│  └──────────────┘    └──────────────┘    └──────┬───────┘   │
│                                                  │           │
└──────────────────────────────────────────────────┼───────────┘
                                                   │ TCP
                                                   │ (可靠传输)
                                                   ▼
┌─────────────────────────────────────────────────────────────┐
│                        服务端 (Server)                        │
│                                                             │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐   │
│  │ InputInjector│◀───│InputTransport│◀───│  TCP Socket │   │
│  │ (SendInput)  │    │   (Server)   │    │   Listen     │   │
│  │              │    │              │    │   port 47989 │   │
│  └──────────────┘    └──────────────┘    └──────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 为什么用 TCP 而不是 UDP

| 维度 | TCP | UDP |
|------|-----|-----|
| 可靠性 | 保证送达，有序 | 可能丢包、乱序 |
| 延迟 | 略高（握手开销） | 最低 |
| 适用场景 | 输入事件（不能丢） | 视频流（可丢帧） |

**决策**：输入事件使用 TCP。键盘按键如果丢了"释放"事件，会导致服务端按键卡住；鼠标移动丢包会导致轨迹跳跃。视频流用 UDP（可丢帧，延迟低）。

### 1.3 组件职责

| 组件 | 位置 | 职责 |
|------|------|------|
| `InputCollector` | 客户端 | 采集键鼠输入（Raw Input + 键盘钩子），计算鼠标绝对坐标 |
| `InputTransportClient` | 客户端 | TCP 连接服务端，发送 `InputMessage` |
| `InputTransportServer` | 服务端 | TCP 监听，接收 `InputMessage`，连接后发送 `ServerMonitorInfo` |
| `InputInjector` | 服务端 | 通过 `SendInput()` 将事件注入系统输入流 |
| `StreamWindow` | 客户端 | 窗口管理，光标显隐，协调采集器和传输器 |

## 2. 输入事件协议设计

### 2.1 InputMessage 结构（固定 12 字节）

```
文件: Common/Input/InputEvent.h

#pragma pack(push, 1)
struct InputMessage
{
    uint8_t  type;          // 事件类型 (InputEventType)
    uint8_t  button;        // 鼠标按键 (MouseButton)
    uint16_t key_code;      // 虚拟键码 (VK_xxx)
    int16_t  dx;            // 鼠标 X（相对位移 或 绝对坐标低位）
    int16_t  dy;            // 鼠标 Y（相对位移 或 绝对坐标高位）
    int16_t  wheel_delta;   // 滚轮滚动量
    uint8_t  reserved;      // 填 0
    uint8_t  reserved2;     // 补齐到 12 字节
};
#pragma pack(pop)

static_assert(sizeof(InputMessage) == 12, "InputMessage 必须为 12 字节");
```

**设计要点**：
- 所有事件类型复用同一个结构体，用 `type` 字段区分含义
- 固定 12 字节，TCP 接收端用 `MSG_WAITALL` 一次 `recv` 读完整消息
- `reserved2` 字段补齐到 4 字节对齐，避免结构体填充问题
- `dx/dy` 是 `int16_t`，存储 `uint16_t` 绝对坐标时用位转换（`static_cast<int16_t>(uint16_t_value)`）

### 2.2 事件类型

```cpp
enum class InputEventType : uint8_t
{
    KeyPress      = 0x01,   // 键盘按下
    KeyRelease    = 0x02,   // 键盘释放
    MouseMove     = 0x03,   // 鼠标移动（相对位移）
    MouseMoveAbs  = 0x08,   // 鼠标移动（绝对坐标 0-65535）
    MouseBtnDown  = 0x04,   // 鼠标按键按下
    MouseBtnUp    = 0x05,   // 鼠标按键释放
    MouseWheel    = 0x06,   // 鼠标垂直滚轮
    MouseHWheel   = 0x07,   // 鼠标水平滚轮
};
```

### 2.3 ServerMonitorInfo 结构（固定 16 字节）

```
文件: Common/Input/InputEvent.h

#pragma pack(push, 1)
struct ServerMonitorInfo
{
    uint16_t capture_width;    // 捕获的显示器分辨率宽度
    uint16_t capture_height;   // 捕获的显示器分辨率高度
    int16_t  monitor_x;        // 显示器在虚拟桌面中的 X 偏移
    int16_t  monitor_y;        // 显示器在虚拟桌面中的 Y 偏移
    uint32_t virtual_width;    // 虚拟桌面总宽度（所有显示器拼接）
    uint32_t virtual_height;   // 虚拟桌面总高度
};
#pragma pack(pop)

static_assert(sizeof(ServerMonitorInfo) == 16, "ServerMonitorInfo 必须为 16 字节");
```

**作用**：TCP 连接建立后，服务端立即发送此结构给客户端。客户端用它做正确的多显示器坐标映射。

## 3. TCP 控制信道

### 3.1 连接握手流程

```
客户端                              服务端
  │                                   │
  │ ──── TCP SYN ───────────────────▶ │  Listen(port 47989)
  │                                   │
  │ ◀──── TCP SYN-ACK ───────────────  │
  │                                   │
  │ ──── TCP ACK ───────────────────▶ │
  │                                   │
  │ ◀──── ServerMonitorInfo (16B) ───  │  Accept 后立即发送
  │                                   │
  │ ──── InputMessage (12B) ────────▶ │  开始发送输入事件
  │ ──── InputMessage (12B) ────────▶ │
  │         ...                       │
```

### 3.2 服务端实现

```cpp
// 文件: Common/Input/InputTransport.cpp

// 接受连接线程（循环等待，客户端断开后重新 accept）
void InputTransportServer::AcceptLoop()
{
    qDebug() << "[InputServer] 等待客户端连接...";

    while (running_)
    {
        // ---- 阻塞等待客户端连接 ----
        sockaddr_in client_addr{};
        int addr_len = sizeof(client_addr);
        SOCKET new_sock = accept(listen_sock_, (sockaddr*)&client_addr, &addr_len);

        if (!running_ || new_sock == INVALID_SOCKET)
            break;                      // 服务端停止或监听 socket 已关闭

        // ---- 禁用 Nagle 算法 ----
        int nodelay = 1;
        setsockopt(new_sock, IPPROTO_TCP, TCP_NODELAY,
                   (const char*)&nodelay, sizeof(nodelay));

        // ---- 发送显示器信息（客户端需要此信息做正确的坐标映射） ----
        if (has_monitor_info_)
        {
            int ret = send(new_sock, (const char*)&monitor_info_,
                           sizeof(ServerMonitorInfo), 0);
            if (ret != sizeof(ServerMonitorInfo))
            {
                closesocket(new_sock);
                continue;               // 发送失败 → 等待下一个连接
            }
        }

        // ---- 同步运行接收循环，直到客户端断开 ----
        ReceiveLoop(new_sock);

        closesocket(new_sock);          // 清理已断开的连接
        qDebug() << "[InputServer] 等待下一个客户端连接...";
    }
}

// 接收线程：阻塞读取 12 字节 InputMessage
void InputTransportServer::ReceiveLoop(SOCKET client_sock)
{
    InputMessage msg{};
    while (running_)
    {
        int ret = recv(client_sock, (char*)&msg, sizeof(InputMessage), MSG_WAITALL);
        if (ret <= 0)
            break;                          // 连接断开
        if (ret != sizeof(InputMessage))
            continue;                       // 不完整消息，丢弃
        if (OnInputEvent)
            OnInputEvent(msg);              // 回调注入器
    }
}
```

**重连修复**：旧版 `AcceptLoop` 只 `accept` 一次就退出，客户端断开后无法重连。新版改为 `while (running_)` 循环，每次 `ReceiveLoop` 返回（客户端断开）后继续 `accept` 下一个连接。移除了独立的 `recv_thread_`，改为在 `AcceptLoop` 线程内同步调用 `ReceiveLoop`，简化线程管理。

## 4. 客户端输入采集

### 4.1 架构设计

`InputCollector` 在独立线程中运行，内部创建一个**隐藏消息窗口**（`HWND_MESSAGE`）来接收 Raw Input 消息。

```
┌─────────────────────────────────────────────┐
│              InputCollector 线程              │
│                                             │
│  ┌─────────────┐    ┌──────────────────┐    │
│  │ 隐藏窗口     │    │  WH_KEYBOARD_LL  │    │
│  │ (HWND_MESSAGE)│   │  键盘钩子         │    │
│  │             │    │                  │    │
│  │ WM_INPUT ──▶│    │ 回调 ───────────▶│    │
│  │ HandleRawMouse│  │ MakeKeyEvent()   │    │
│  └─────────────┘    └──────────────────┘    │
│         │                    │               │
│         ▼                    ▼               │
│    ┌──────────────────────────────┐         │
│    │   DispatchEvent(InputMessage) │         │
│    │   → OnInputEvent 回调         │         │
│    └──────────────────────────────┘         │
└─────────────────────────────────────────────┘
```

### 4.2 为什么用 Raw Input 而不是普通鼠标消息

| 方案 | 优点 | 缺点 |
|------|------|------|
| `WM_MOUSEMOVE` | 简单 | 窗口不在前台时收不到 |
| `WH_MOUSE_LL` 钩子 | 全局捕获 | 只能拿到相对位移，延迟高 |
| **Raw Input** | **硬件级捕获，窗口不在前台也能收到** | 需要隐藏窗口做消息泵 |

**决策**：鼠标用 Raw Input（`RIDEV_INPUTSINK` 标志确保即使窗口不在前台也能接收），键盘用 `WH_KEYBOARD_LL` 低级钩子。

### 4.3 Raw Input 注册

### 4.4 鼠标数据处理

```cpp
// 文件: Common/Input/InputCollector.cpp

void InputCollector::HandleRawMouse(const RAWMOUSE& rm)
{
    // ---- 第一步：获取光标在视频窗口内的绝对坐标 ----
    uint16_t abs_x = 0, abs_y = 0;
    bool inside = GetCursorAbsPos(abs_x, abs_y);

    // ---- 第二步：移动（仅光标在窗口内时发送） ----
    // Raw Input 检测"鼠标在动"，但发送的是绝对坐标而非相对增量
    if (inside && (rm.usFlags & MOUSE_MOVE_ABSOLUTE) == 0)
    {
        if (rm.lLastX != 0 || rm.lLastY != 0)
        {
            DispatchEvent(MakeMouseMoveAbsEvent(abs_x, abs_y));
        }
    }

    // ---- 第三步：鼠标按键（光标在窗口外不发送） ----
    if (!inside)
        return;

    USHORT btn_flags = rm.usButtonFlags;
    if (btn_flags & RI_MOUSE_LEFT_BUTTON_DOWN)
        DispatchEvent(MakeMouseButtonEvent(MouseButton::Left, true));
    // ... 其他按键 ...

    // ---- 第四步：滚轮 ----
    if (btn_flags & RI_MOUSE_WHEEL)
    {
        int16_t delta = static_cast<int16_t>(rm.usButtonData);
        DispatchEvent(MakeMouseWheelEvent(delta));
    }
}
```

**关键点**：Raw Input 只用于检测"鼠标硬件在动"（`lLastX/lLastY != 0`），但实际发送的坐标不是 Raw Input 的相对增量，而是通过 `GetCursorPos + ScreenToClient` 计算的绝对坐标。这消除了相对位移的累积误差。

```cpp
LRESULT CALLBACK InputCollector::KeyboardProc(int nCode, WPARAM wParam, LPARAM lParam)
{
    if (nCode == HC_ACTION && instance_ && instance_->active_)
    {
        KBDLLHOOKSTRUCT* kb = reinterpret_cast<KBDLLHOOKSTRUCT*>(lParam);

        bool down = false;
        switch (wParam)

        case WM_SYSKEYDOWN:

        case WM_SYSKEYUP:
            down = false;
            break;

        }

        instance_->DispatchEvent(msg);
    }

pass:
    return CallNextHookEx(nullptr, nCode, wParam, lParam);
}
```

## 5. 服务端输入注入

### 5.1 键盘注入：Scancode 优先

```cpp
// 文件: Common/Input/InputInjector.cpp

void InputInjector::InjectKeyboard(uint16_t vk_code, bool down)
{
    INPUT input{};
    input.type = INPUT_KEYBOARD;
    auto& ki = input.ki;

    // ---- VK → Scancode 查表 ----
    // Scancode 对游戏兼容性更好，很多游戏只认 Scancode 不认 VK
    ki.wScan = VK_TO_SCANCODE_MAP[vk_code & 0xFF];

    if (ki.wScan)
        ki.dwFlags = KEYEVENTF_SCANCODE;    // 有映射 → 用 Scancode
    else
        ki.wVk = vk_code;                   // 无映射 → 回退到 VK

    // ---- 扩展键标记 ----
    // PS/2 协议中这些键需要 Extended 前缀字节
    switch (vk_code)
    {
    case VK_RWIN:
    case VK_RMENU:
    case VK_RCONTROL:
    case VK_INSERT:
    case VK_DELETE:
    case VK_HOME:
    case VK_END:
    case VK_PRIOR:
    case VK_NEXT:
    case VK_UP:
    case VK_DOWN:
    case VK_LEFT:
    case VK_RIGHT:
    case VK_DIVIDE:
    case VK_APPS:
        ki.dwFlags |= KEYEVENTF_EXTENDEDKEY;
        break;
    }

    if (!down)
        ki.dwFlags |= KEYEVENTF_KEYUP;

    SendInputWithRetry(input);
}
```

**为什么用 Scancode**：游戏通常只认 Scancode（硬件扫描码），不认 VK 码（虚拟键码）。比如某些游戏按 WASD 移动，如果发 VK 码可能没反应，但发 Scancode 就能工作。这套 VK→Scancode 映射表抄自 Sunshine `src/platform/windows/keylayout.h`。

### 5.2 UAC 桌面切换重试

```cpp
// 文件: Common/Input/InputInjector.cpp

// SendInput 失败时切换桌面后重试一次
void SendInputWithRetry(INPUT& input)
{
retry:
    if (SendInput(1, &input, sizeof(INPUT)) != 1)
    {
        HDESK hdesk = SyncThreadDesktop();
        if (last_known_desktop_ != hdesk)
        {
            last_known_desktop_ = hdesk;
            goto retry;                      // 桌面已切换，重试
        }
        LogManager::Log("ERR", "[InputInjector] SendInput 失败");
    }
}

// 切换到当前输入桌面（UAC 兼容）
HDESK SyncThreadDesktop()
{
    HDESK hdesk = OpenInputDesktop(DF_ALLOWOTHERACCOUNTHOOK, FALSE, GENERIC_ALL);
    if (!hdesk)
        return nullptr;
    SetThreadDesktop(hdesk);
    CloseDesktop(hdesk);
    return hdesk;
}
```

**为什么需要这个**：当 UAC 弹窗或锁屏时，系统切换到 Winlogon 桌面，此时 `SendInput` 会失败。需要先 `SetThreadDesktop` 到当前输入桌面才能注入。抄自 Sunshine `misc.cpp syncThreadDesktop()`。

### 5.3 鼠标绝对坐标注入

```cpp
// 文件: Common/Input/InputInjector.cpp

void InputInjector::InjectMouseMoveAbs(uint16_t x, uint16_t y)
{
    INPUT input{};
    input.type = INPUT_MOUSE;
    input.mi.dwFlags = MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK | MOUSEEVENTF_MOVE;
    input.mi.dx = x;
    input.mi.dy = y;

    SendInputWithRetry(input);
}
```

**三个 Flag 的含义**：
- `MOUSEEVENTF_MOVE`：表示这是一次移动事件
- `MOUSEEVENTF_ABSOLUTE`：使用绝对坐标（0-65535）而非相对位移
- `MOUSEEVENTF_VIRTUALDESK`：坐标系覆盖整个虚拟桌面（多显示器拼接），而非仅主显示器

## 6. 鼠标坐标映射（核心难点）

### 6.1 问题背景

`MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK` 把 `0-65535` 映射到**整个虚拟桌面**。如果服务器有双显示器（比如 3840×1080），捕获的是左边那台（1920×1080，偏移 0,0），客户端光标在窗口中间（归一化后 32767, 32767），`SendInput` 会把光标放到虚拟桌面中间，即 `(1920, 540)` —— 正好是两台显示器的分界线，而不是左边显示器的中间。

### 6.2 解决方案：ServerMonitorInfo

服务端在 TCP 连接建立后，发送 `ServerMonitorInfo` 给客户端，包含：
- 捕获的显示器分辨率 `capture_width × capture_height`
- 显示器在虚拟桌面中的偏移 `monitor_x, monitor_y`
- 虚拟桌面总尺寸 `virtual_width × virtual_height`

### 6.3 映射公式

```
输入：客户端窗口坐标 (client_x, client_y)，窗口尺寸 (widget_w, widget_h)
     ServerMonitorInfo: capture_w, capture_h, monitor_x, monitor_y, virtual_w, virtual_h

第 1 步：客户端窗口坐标 → 服务器捕获分辨率坐标
  server_x = (client_x / widget_w) × capture_w
  server_y = (client_y / widget_h) × capture_h

第 2 步：加上显示器在虚拟桌面中的偏移
  server_x += monitor_x
  server_y += monitor_y

第 3 步：归一化到 0-65535（基于虚拟桌面尺寸）
  out_x = (server_x / virtual_w) × 65535
  out_y = (server_y / virtual_h) × 65535
```

### 6.4 验证

**单显示器 1920×1080**：
- `capture = 1920×1080, monitor_x/y = 0, virtual = 1920×1080`
- 客户端在窗口中间 (960, 540)，widget 为 1920×1080
- `server_x = 960/1920 × 1920 + 0 = 960`
- `out_x = 960/1920 × 65535 = 32767` ✅

**双显示器，捕获右边那台**：

- `capture = 1920×1080, monitor_x = 1920, monitor_y = 0, virtual = 3840×1080`
- 客户端在窗口中间 (960, 540)，widget 为 1920×1080
- `server_x = 960/1920 × 1920 + 1920 = 2880`
- `out_x = 2880/3840 × 65535 = 49152`
- `SendInput` 映射到虚拟桌面 (2880, 540) = 右边显示器 (960, 540) ✅

### 6.5 代码实现

```cpp
// 文件: Common/Input/InputCollector.cpp

bool InputCollector::GetCursorAbsPos(uint16_t& out_x, uint16_t& out_y)
{
    if (!video_hwnd_ || !IsWindow(video_hwnd_))
        return false;

    // ---- 第一步：获取光标屏幕坐标 ----
    POINT pt;
    if (!GetCursorPos(&pt))
        return false;

    // ---- 第二步：转换为视频窗口客户区坐标 ----
    if (!ScreenToClient(video_hwnd_, &pt))
        return false;

    // ---- 第三步：获取视频窗口客户区尺寸 ----
    RECT rect;
    if (!GetClientRect(video_hwnd_, &rect))
        return false;

    int width = rect.right - rect.left;
    int height = rect.bottom - rect.top;
    if (width <= 0 || height <= 0)
        return false;

    // ---- 第四步：检查光标是否在窗口内 ----
    if (pt.x < 0 || pt.y < 0 || pt.x > width || pt.y > height)
        return false;                        // 光标在窗口外，不发送事件

    // ---- 第五步：钳制到窗口内 ----
    if (pt.x < 0) pt.x = 0;
    if (pt.y < 0) pt.y = 0;
    if (pt.x >= width) pt.x = width - 1;
    if (pt.y >= height) pt.y = height - 1;

    // ---- 第六步：归一化到 0-65535 ----
    if (has_monitor_info_)
    {
        float cap_w = static_cast<float>(monitor_info_.capture_width);
        float cap_h = static_cast<float>(monitor_info_.capture_height);
        float virt_w = static_cast<float>(monitor_info_.virtual_width);
        float virt_h = static_cast<float>(monitor_info_.virtual_height);

        // 客户端窗口坐标 → 服务器捕获分辨率坐标
        float server_x = static_cast<float>(pt.x) / width * cap_w;
        float server_y = static_cast<float>(pt.y) / height * cap_h;

        // 加上显示器在虚拟桌面中的偏移
        server_x += static_cast<float>(monitor_info_.monitor_x);
        server_y += static_cast<float>(monitor_info_.monitor_y);

        // 归一化到 0-65535（基于虚拟桌面尺寸）
        out_x = static_cast<uint16_t>(server_x / virt_w * 65535.0f);
        out_y = static_cast<uint16_t>(server_y / virt_h * 65535.0f);
    }
    else
    {
        // 无显示器信息 → 回退到简单归一化（单显示器场景）
        out_x = static_cast<uint16_t>((static_cast<float>(pt.x) / width) * 65535.0f);
        out_y = static_cast<uint16_t>((static_cast<float>(pt.y) / height) * 65535.0f);
    }

    return true;
}
```

## 7. 光标显隐策略

### 7.1 问题：双光标

如果不做处理，客户端会同时看到两个光标：
1. **本地系统光标**（客户端 OS 绘制）
2. **服务端合成光标**（服务端 `CursorCapture` 抓取光标形状，渲染到 H.264 画面中）

两个光标位置可能不完全重合（网络延迟、坐标映射误差），导致视觉上看到两个光标在闪烁。

### 7.2 最终方案：客户端本地光标（第三阶段定稿）

经过多轮迭代后，最终放弃了服务端光标合成路线，改用**客户端本地光标**方案：

**核心思路**：

逻辑上是本地光标在客户端窗口与 server 窗口尺寸之间的位置映射。只要帧率够快（如 120 帧），本地光标和虚拟光标其实是实时响应的，用户感知不到差异。因此直接用本地光标，不再在服务端合成光标到 H.264 画面。

**效果**：
- 客户端实时显示本地光标
- `ObsNvencEncoderFast::EncodeFrame` 的 cursor 参数已标记为忽略（`/*cursor*/`），不再做服务端合成

### 7.3 为什么放弃服务端光标合成

| 方案 | 优点 | 缺点 |
|------|------|------|
| 服务端合成（旧） | 光标形状与服务端完全一致 | 网络延迟导致光标 lag；CursorCapture 在某些场景失败（记事本编辑）；消耗编码 CPU |
| **客户端本地光标（最终）** | **零延迟响应；无 CaptureIcon 失败问题；编码器更简单** | 光标形状与服务端可能略有差异（通常无感知） |

在高帧率（120fps）下，本地光标的位置映射几乎是实时的，用户完全感知不到本地光标与服务端画面的偏差。这比服务端合成方案简单得多，且可靠性更高。

### 7.4 CursorCapture 代码保留

`CursorCapture` 代码仍然保留在项目中（`Server/OBS_Capture/CursorCapture.h/.cpp`），但 `StreamServer::Run()` 中获取光标信息的代码已注释掉，`ObsNvencEncoderFast` 的 `EncodeFrame` 不再使用 cursor 参数。如果未来需要恢复服务端合成（如低帧率场景），取消注释即可。

```cpp
{
```

```cpp
    SDL_AtomicLock(&m_MousePositionLock);

    m_MousePositionReport.y = mouseY;
```

#### 8.2.3 定时刷新 + 坐标映射（核心）

每 5ms 由定时器触发：

```cpp
// 文件: moonlight/app/streaming/input/mouse.cpp:97

void SdlInputHandler::flushMousePositionUpdate()
{
    bool hasNewPosition = SDL_AtomicSet(&m_MousePositionUpdated, 0) != 0;
    if (hasNewPosition) {
        if (SDL_AtomicTryLock(&m_MousePositionLock)) {
            SDL_Rect src, dst;
            bool mouseInVideoRegion;

            src.x = src.y = 0;
            src.w = m_StreamWidth;       // 流画面宽
            src.h = m_StreamHeight;      // 流画面高

            dst.x = dst.y = 0;
            dst.w = m_MousePositionReport.windowWidth;   // 窗口宽
            dst.h = m_MousePositionReport.windowHeight;  // 窗口高

            // 计算视频区域在窗口中的实际位置（保持宽高比，letterbox/pillarbox）
            StreamUtils::scaleSourceToDestinationSurface(&src, &dst);

            mouseInVideoRegion = isMouseInVideoRegion(...);

            // 钳制到视频区域内
            short x = qMin(qMax(m_MousePositionReport.x - dst.x, 0), dst.w);
            short y = qMin(qMax(m_MousePositionReport.y - dst.y, 0), dst.h);

            SDL_AtomicUnlock(&m_MousePositionLock);

            // 发送：视频区域内的相对坐标 + 视频区域尺寸
            if (mouseInVideoRegion || m_MouseWasInVideoRegion || ...) {
                LiSendMousePositionEvent(x, y, dst.w, dst.h);
            }

            // 光标显隐切换
            if (mouseInVideoRegion ^ m_MouseWasInVideoRegion) {
                SDL_Event event;
                event.type = SDL_USEREVENT;
                event.user.code = (mouseInVideoRegion &&
                    m_MouseCursorCapturedVisibilityState == SDL_DISABLE) ?
                    SDL_CODE_HIDE_CURSOR : SDL_CODE_SHOW_CURSOR;
                SDL_PushEvent(&event);
            }

            m_MouseWasInVideoRegion = mouseInVideoRegion;
        }
    }
}
```

#### 8.2.4 视频区域缩放算法

```cpp
// 文件: moonlight/app/streaming/streamutils.cpp:18

void StreamUtils::scaleSourceToDestinationSurface(SDL_Rect* src, SDL_Rect* dst)
{
    int dstH = SDL_ceilf((float)dst->w * src->h / src->w);  // 按宽度比例算高度
    int dstW = SDL_ceilf((float)dst->h * src->w / src->h);  // 按高度比例算宽度

    if (dstH > dst->h) {
        // 高度超出窗口 → 按宽度适配，居中 (letterbox)
        dst->x += (dst->w - dstW) / 2;
        dst->w = dstW;
    }
    else {
        // 宽度超出窗口 → 按高度适配，居中 (pillarbox)
        dst->y += (dst->h - dstH) / 2;
        dst->h = dstH;
    }
}
```

### 8.3 Moonlight 发送的不是归一化坐标

**关键区别**：Moonlight 客户端发送的是 `(x, y, width, height)` —— 视频区域内的**原始像素坐标**和视频区域尺寸，**不是** 0-65535 归一化坐标。坐标映射由**服务端 Sunshine** 完成。

### 8.4 Sunshine 服务端坐标映射

```cpp
// 文件: moonlight/Sunshine-0.23.1/src/input.cpp:475

std::optional<std::pair<float, float>>
client_to_touchport(std::shared_ptr<input_t> &input,
                     const std::pair<float, float> &val,
                     const std::pair<float, float> &size)
{
    auto &touch_port = input->touch_port;

    // 客户端坐标 → touchport 坐标
    auto scalarX = touch_port.width / size.first;
    auto scalarY = touch_port.height / size.second;

    float x = std::clamp(val.first, 0.0f, size.first) * scalarX;
    float y = std::clamp(val.second, 0.0f, size.second) * scalarY;

    auto offsetX = touch_port.client_offsetX;
    auto offsetY = touch_port.client_offsetY;

    x = std::clamp(x, offsetX, (size.first * scalarX) - offsetX);
    y = std::clamp(y, offsetY, (size.second * scalarY) - offsetY);

    return std::pair { (x - offsetX) * touch_port.scalar_inv,
                       (y - offsetY) * touch_port.scalar_inv };
}
```

## 9. 我们 vs Moonlight 方案对比

### 9.1 架构对比

| 维度 | 我们的方案 | Moonlight 方案 |
|------|-----------|---------------|
| 传输协议 | TCP（自定义 12 字节消息） | TCP（Moonlight 协议） |
| 鼠标采集 | Raw Input（隐藏窗口） | SDL 事件（`SDL_MouseMotionEvent`） |
| 键盘采集 | `WH_KEYBOARD_LL` 钩子 | SDL 事件（`SDL_KeyboardEvent`） |
| 坐标发送 | 客户端做完整映射，发送 0-65535 | 客户端发送原始像素坐标，服务端做映射 |
| 显示器信息 | TCP 握手时发送 `ServerMonitorInfo` | 服务端 `touch_port` 动态维护 |
| 光标显隐 | `QEvent::Enter/Leave` + `setCursor` | `SDL_ShowCursor` + 视频区域检测 |
| 光标形状 | 服务端合成到 H.264 画面 | 服务端合成到 H.264 画面 |
| 区域锁定 | 不锁定（允许光标离开窗口） | SDL `SetWindowMouseRect`（可选） |
| 刷新频率 | Raw Input 事件驱动 | 5ms 定时器轮询 |

### 9.2 坐标映射对比

| 维度 | 我们的方案 | Moonlight 方案 |
|------|-----------|---------------|
| 客户端发送 | `0-65535` 归一化坐标 | `(x, y, width, height)` 原始像素 |
| 映射位置 | **客户端**完成全部计算 | **服务端**完成最终映射 |
| 多显示器 | `ServerMonitorInfo` + 偏移计算 | `touch_port` + `offset_x/y` |
| Letterbox 处理 | 未实现（假设视频填满窗口） | `scaleSourceToDestinationSurface` |
| 钳制策略 | 钳制到窗口边界 | 钳制到视频区域 |

### 9.3 我们方案的优势

- 坐标映射在客户端完成，服务端注入逻辑简单
- 不依赖 SDL，直接用 Win32 API
- TCP 握手时一次性传递显示器信息，无需动态维护

### 9.4 我们方案的不足（待改进）

- **未处理 Letterbox/Pillarbox**：如果视频画面没有填满窗口（宽高比不同），坐标会有偏差。Moonlight 用 `scaleSourceToDestinationSurface` 计算实际视频区域
- **未实现按钮事件前的位置刷新**：Moonlight 在发送按钮事件前会先 `flushMousePositionUpdate()`，确保光标在正确位置。我们的方案靠 Raw Input 事件驱动，可能存在按钮事件时坐标还没更新的情况
- **未实现拖拽出窗口的捕获**：Moonlight 在鼠标离开窗口但按钮仍按下时，用 `SDL_CaptureMouse` 继续跟踪

## 10. 踩坑记录与技术决策

### 10.1 VIRTUALDESK 导致多显示器光标错位

**现象**：双显示器环境下，客户端光标在窗口中间，服务端光标跑到了另一台显示器上。

**原因**：`MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK` 把 `0-65535` 映射到整个虚拟桌面（3840×1080），而不是单个显示器（1920×1080）。简单的 `client_x / widget_w × 65535` 归一化只对单显示器有效。

**修复**：引入 `ServerMonitorInfo`，客户端做三步映射：窗口坐标 → 捕获分辨率 → 加偏移 → 虚拟桌面归一化。

### 10.2 ClipCursor 限制用户操作

**现象**：串流时鼠标被限制在客户端窗口内，用户无法操作其他软件。

**原因**：之前用 `ClipCursor(&rect)` 限制光标在视频窗口内。

**修复**：完全移除 `ClipCursor`。光标可以自由离开窗口，离开后不发送输入事件。

### 10.3 双光标问题

**现象**：客户端同时看到本地光标和服务端渲染的光标。

**修复**：鼠标进入视频窗口时 `setCursor(Qt::BlankCursor)` 隐藏本地光标，离开时恢复。类似 ToDesk 的体验。

### 10.4 重连后光标位置不更新

**现象**：断开重连后，鼠标静止不动时服务端不知道光标位置。

**原因**：Raw Input 只在鼠标硬件移动时触发，重连时鼠标静止无法触发事件。

**修复**：`StreamWindow::StartInput()` 中主动发送一次初始光标位置：

```cpp
uint16_t init_x = 0, init_y = 0;
if (input_collector_->GetCursorAbsPos(init_x, init_y))
{
    InputMessage msg = MakeMouseMoveAbsEvent(init_x, init_y);
    input_transport_->Send(msg);
}
```

### 10.5 CursorCapture 失败导致光标消失

**现象**：在记事本中编辑文字时光标消失。

**原因**：Windows 使用临时空白光标句柄，`CaptureIcon` 失败后 `visible_` 被设为 false。

**修复**：`visible_` 仅依赖 `CURSOR_SHOWING` 标志位，不与 `CaptureIcon` 成功耦合。`CaptureIcon` 失败时保留旧位图缓存。

### 10.6 SendInput 在 UAC 桌面失败

**现象**：UAC 弹窗时输入注入失效。

**原因**：UAC 弹窗时系统切换到 Winlogon 桌面，`SendInput` 在错误桌面上执行。

**修复**：`SendInputWithRetry` 失败时调用 `SyncThreadDesktop()` 切换到当前输入桌面，然后重试。抄自 Sunshine `misc.cpp`。

### 10.7 技术决策说明：为什么不用 SDL

**为什么是这个方案**：
我们的项目是纯 Win32 + Qt，不依赖 SDL。直接用 Raw Input API 可以获得更底层的控制，且不需要引入额外依赖。

**底层是什么**：
Raw Input 直接从 HID 驱动读取数据，`RIDEV_INPUTSINK` 标志让隐藏窗口也能接收输入，这是 Win32 提供的硬件级输入捕获机制。

**如果是你你会怎么学**：
如果想深入这个方向，看 Win32 SDK 文档中 "Raw Input" 章节，以及 Moonlight 的 `input.cpp` 了解 SDL 如何封装这些 API。

### 10.8 AcceptLoop 单次 accept 导致重连失败

**现象**：客户端第一次连接正常，断开后第二次连接鼠标完全不动。

**原因**：旧版 `AcceptLoop` 只 `accept` 一次就退出函数，监听线程结束。客户端断开后 `ReceiveLoop` 也退出，但没有线程在 `accept` 新连接。

**修复**：`AcceptLoop` 改为 `while (running_)` 循环，每次 `ReceiveLoop` 返回后继续 `accept` 下一个连接。移除独立的 `recv_thread_`，改为在 `AcceptLoop` 线程内同步调用 `ReceiveLoop`。

### 10.9 D3D11 Video Processor 色彩空间不设置导致发青

**现象**：使用 `ObsNvencEncoderFast`（GPU 硬件色彩转换）后，客户端看到的画面整体发青。

**原因**：创建 Video Processor 后未设置色彩空间，驱动用 `undefined` 默认值做 RGB→YUV 转换，UV 通道产生直流偏移。同时编码器未设置 VUI 参数，解码器收到 `unspecified` 按默认 limited range 解析，造成二次偏色。

**修复**：
1. 用 `ID3D11VideoContext1` 设置输入 `DXGI_COLOR_SPACE_RGB_FULL_G22_NONE_P709`、输出 `DXGI_COLOR_SPACE_YCBCR_FULL_G22_LEFT_P709`
2. 编码器设置 `color_range = AVCOL_RANGE_JPEG`、`colorspace = AVCOL_SPC_BT709` 等 VUI 参数
3. `AVFrame` 也设置对应的 `color_range` 和 `colorspace`

### 10.10 ID3D11VideoContext1 头文件和 API 命名坑

**现象**：编译报 `ID3D11VideoContext1` 未声明、`VideoProcessorSetInputColorSpace1` 不存在。

**原因**：
1. `ID3D11VideoContext1` 声明在 `d3d11_3.h`，不在 `dxgi1_5.h` 中
2. D3D11 Video Processor 的色彩空间 API 命名规则：输入侧永远是 `Stream`（按流设置），没有 `Input` 版本。正确方法是 `VideoProcessorSetStreamColorSpace1`，不是 `VideoProcessorSetInputColorSpace1`

**修复**：`#include <d3d11_3.h>`，调用 `VideoProcessorSetStreamColorSpace1`（输入）和 `VideoProcessorSetOutputColorSpace1`（输出）。

## 11. 编码器抽象接口与 GPU 硬件色彩转换

### 11.1 编码器抽象基类 IVideoEncoder

第三阶段后期引入了 `IVideoEncoder` 抽象基类，统一 `ObsNvencEncoder`（CPU sws_scale）和 `ObsNvencEncoderFast`（GPU VideoProcessor）的接口：

```cpp
// 文件: Server/OBS_Capture/IVideoEncoder.h

class IVideoEncoder
{
public:
    virtual ~IVideoEncoder() = default;

    virtual bool Init(ID3D11Device* d3d_device, int width, int height,
                      int fps, int bitrate_kbps) = 0;

    virtual bool EncodeFrame(ID3D11Texture2D* texture, uint64_t frame_index,
                             bool force_idr, std::vector<uint8_t>& out_data,
                             const CursorInfo* cursor = nullptr,
                             int monitor_x = 0, int monitor_y = 0) = 0;

    virtual void Flush(std::function<void(const std::vector<uint8_t>&)> on_packet) = 0;
    virtual void Release() = 0;
    virtual bool IsReady() const = 0;
};
```

`StreamServer` 通过单指针 `encoder_` + `use_fast` 参数选择实现：

```cpp
// 文件: Server/StreamServer.cpp

if (use_fast)
{
    encoder_ = new ObsNvencEncoderFast();     // GPU 硬件色彩转换
}
else
{
    encoder_ = new ObsNvencEncoder();          // CPU 软件色彩转换
}
encoder_->Init(d3d_device_, width_, height_, fps_, bitrate_kbps);
```

命令行 `--fast` 开关控制：

```cpp
// 文件: App/main.cpp

bool use_fast = HasArg("--fast", argc, argv);
server.Init(port, monitor_index, dest_ip, fps, bitrate, ctrl_port, use_fast);
```

**为什么用抽象基类**：两个编码器的 `Init`/`EncodeFrame`/`Flush`/`Release` 签名完全一致，只是内部实现不同。C++ 的 virtual 多态就是为这种场景设计的——调用方 `StreamServer::Run()` 零分支，只写一行 `encoder_->EncodeFrame(...)`。`std::variant` 需要写 `std::visit` + lambda，代码更绕且没有额外收益。

### 11.2 ObsNvencEncoderFast：GPU 硬件色彩转换

#### 11.2.1 数据流对比

```
旧版 (ObsNvencEncoder)：
  GPU 纹理 → CopyResource → staging 纹理 → Map → CPU BGRA
           → sws_scale (CPU) → CPU NV12 → NVENC 编码

新版 (ObsNvencEncoderFast)：
  GPU 纹理 → VideoProcessorBlt → GPU NV12 纹理
           → CopyResource → staging 纹理 → Map → CPU NV12 → NVENC 编码
```

核心区别：`sws_scale` 的 CPU 色彩转换被 D3D11 Video Processor 的 GPU 固定功能单元替代，消除了 CPU 瓶颈。

#### 11.2.2 D3D11 Video Processor 初始化

```cpp
// 文件: Server/OBS_Capture/ObsNvencEncoderFast.cpp

bool ObsNvencEncoderFast::InitVideoProcessor()
{
    // 1. 获取 Video Device 和 Context 接口
    d3d_device_->QueryInterface(__uuidof(ID3D11VideoDevice), (void**)&video_device_);
    d3d_ctx_->QueryInterface(__uuidof(ID3D11VideoContext), (void**)&video_ctx_);

    // 2. 创建 Video Processor Enumerator
    D3D11_VIDEO_PROCESSOR_CONTENT_DESC content_desc = {};
    content_desc.InputFrameFormat = D3D11_VIDEO_FRAME_FORMAT_PROGRESSIVE;
    content_desc.InputWidth = width_;
    content_desc.InputHeight = height_;
    content_desc.OutputWidth = width_;
    content_desc.OutputHeight = height_;
    video_device_->CreateVideoProcessorEnumerator(&content_desc, &video_proc_enum_);

    // 3. 检查格式支持（BGRA 输入、NV12 输出）
    // ...

    // 4. 创建 Video Processor 实例
    video_device_->CreateVideoProcessor(video_proc_enum_, 0, &video_processor_);

    // 5. 设置色彩空间（关键！见 11.3 节）
    // ...

    return true;
}
```

#### 11.2.3 GPU 格式转换

```cpp
// 文件: Server/OBS_Capture/ObsNvencEncoderFast.cpp

bool ObsNvencEncoderFast::ConvertBgraToNv12Gpu(ID3D11Texture2D* src_bgra)
{
    // 1. 创建输入视图（指向源 BGRA 纹理）
    ID3D11VideoProcessorInputView* input_view = nullptr;
    video_device_->CreateVideoProcessorInputView(src_bgra, video_proc_enum_, ...);

    // 2. 创建输出视图（指向目标 NV12 纹理）
    ID3D11VideoProcessorOutputView* output_view = nullptr;
    video_device_->CreateVideoProcessorOutputView(nv12_texture_, video_proc_enum_, ...);

    // 3. 执行转换 —— GPU 硬件一步完成 BGRA→NV12
    D3D11_VIDEO_PROCESSOR_STREAM stream = {};
    stream.Enable = TRUE;
    stream.pInputSurface = input_view;
    video_ctx_->VideoProcessorBlt(video_processor_, output_view, 0, 1, &stream);

    return true;
}
```

### 11.3 色彩空间设置（修复发青的关键）

#### 11.3.1 问题

不设置色彩空间时，驱动用 `undefined` 默认值做 RGB→YUV 转换，UV 通道产生直流偏移，画面整体发青。同时编码器未设置 VUI 参数，解码器收到 `unspecified` 按默认 limited range 解析，造成二次偏色。

#### 11.3.2 修复

**三层都要设置色彩信息**：

```cpp
// ---- 第 1 层：Video Processor 色彩空间（GPU 转换时用） ----
// 文件: ObsNvencEncoderFast.cpp → InitVideoProcessor()

ID3D11VideoContext1* video_ctx1 = nullptr;
video_ctx_->QueryInterface(__uuidof(ID3D11VideoContext1), (void**)&video_ctx1);

// 输入：BGRA = RGB full range (0-255), gamma 2.2, BT.709
// 注意：方法名是 StreamColorSpace1（按流设置），不是 InputColorSpace1（不存在）
video_ctx1->VideoProcessorSetStreamColorSpace1(
    video_processor_, 0, DXGI_COLOR_SPACE_RGB_FULL_G22_NONE_P709);

// 输出：NV12 = YCbCr full range (0-255), gamma 2.2, BT.709, 4:2:0 left chroma
video_ctx1->VideoProcessorSetOutputColorSpace1(
    video_processor_, DXGI_COLOR_SPACE_YCBCR_FULL_G22_LEFT_P709);
```

```cpp
// ---- 第 2 层：编码器 VUI 参数（写入 H.264 SPS，告诉解码器） ----
// 文件: ObsNvencEncoderFast.cpp → Init()

codec_ctx_->color_range = AVCOL_RANGE_JPEG;     // full range (0-255)
codec_ctx_->colorspace = AVCOL_SPC_BT709;       // BT.709 色彩矩阵
codec_ctx_->color_primaries = AVCOL_PRI_BT709;  // BT.709 原色
codec_ctx_->color_trc = AVCOL_TRC_BT709;        // BT.709 传输特性
```

```cpp
// ---- 第 3 层：AVFrame 色彩信息（每帧都设置） ----
// 文件: ObsNvencEncoderFast.cpp → EncodeFrame()

frame_->color_range = AVCOL_RANGE_JPEG;   // full range
frame_->colorspace = AVCOL_SPC_BT709;     // BT.709
```

#### 11.3.3 技术决策说明

**为什么是这个方案**：
BGRA→NV12 涉及 RGB→YUV 矩阵运算和 range 压缩。不告诉 Video Processor 输入是 RGB full range、输出用 BT.709 矩阵，驱动用不确定的默认值，UV 通道产生直流偏移 → 发青。同时编码器必须通过 VUI 把色彩信息传递给解码器，否则解码器收到 `unspecified` 按 limited range 解析 full range 数据，造成二次偏色。

**底层是什么**：
D3D11 Video Processor 是 GPU 固定功能单元（显示引擎内部），设置色彩空间后硬件按 BT.709 矩阵做 RGB→YUV 转换，零 CPU 开销。H.264 的 VUI（Video Usability Information）是 SPS 中的元数据，`color_range`/`colorspace` 字段告诉解码器如何还原像素值——解码器读不到就猜 `unspecified`，猜错就偏色。

**如果是你你会怎么学**：
看 Microsoft Docs 的 `ID3D11VideoContext1` 接口和 `DXGI_COLOR_SPACE_TYPE` 枚举说明；FFmpeg 的色彩字段定义在 `libavutil/pixfmt.h`（`AVColorRange`/`AVColorSpace`）；想理解 range/matrix 对画面的影响，看 ITU-R BT.709 标准的第 3 节（转换矩阵推导）。

### 11.4 API 命名规则速查

| 接口 | 输入（按流） | 输出 |
|------|-------------|------|
| `ID3D11VideoContext` | `VideoProcessorSetStreamColorSpace` | `VideoProcessorSetOutputColorSpace` |
| `ID3D11VideoContext1` | `VideoProcessorSetStreamColorSpace1` | `VideoProcessorSetOutputColorSpace1` |

**输入侧永远是 `Stream`（因为是按输入流设置），没有 `Input` 版本**。输出侧才是 `Output`。
