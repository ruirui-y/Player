格式和 `GatewayApp` 的 `server_config.json` 一致，`GlobalConfig::Init()` 直接复用解析逻辑。

### 4.2 数据库：SQLite 替换 MySQL

替换 `SqlExec` 内部的 MySQL Connector/C++ 为 SQLite C API：

```
SqlExec（改造 ~60 行）:
  mysqlx::Session → sqlite3*
  session->sql("SELECT...").execute() → sqlite3_exec() + sqlite3_prepare_v2()
  ConnectionPool → 不需要了，SQLite 单连接足矣
```

数据库结构（2 张表）：

```sql
CREATE TABLE IF NOT EXISTS devices (
    id          TEXT PRIMARY KEY,
    name        TEXT NOT NULL,
    public_ip   TEXT DEFAULT '',
    local_ip    TEXT DEFAULT '',
    status      INTEGER DEFAULT 1,   -- 1=在线 0=离线
    last_seen   INTEGER DEFAULT 0    -- Unix 时间戳
);

CREATE TABLE IF NOT EXISTS bindings (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id   TEXT NOT NULL,
    bind_key    TEXT UNIQUE NOT NULL,
    created_at  INTEGER DEFAULT 0
);
```

### 4.3 STUN 服务器（StunServer.h/.cpp）— ~250 行

```
RFC 5389 Binding Request/Response：

监听 UDP :3478：

客户端发送（20 字节）:
  [0..1]  Type = 0x0001 (Binding Request)
  [2..3]  Length = 0
  [4..19] Transaction ID (16 bytes random)

服务端响应（32 字节）:
  [0..1]  Type = 0x0101 (Binding Success Response)
  [2..3]  Length = 12
  [4..19] Transaction ID (原样返回)
  [20..21] XOR-MAPPED-ADDRESS (type=0x0020, len=8)
  [24]     reserved
  [25]     family = 0x01
  [26..27] XOR port  (port ^ 0x2112)
  [28..31] XOR addr  (addr ^ 0x2112A42F)
```

实现：`recvfrom` → 构造 response → `sendto`。仿 DemandStation 的异步模式，用 Asio 的 `async_receive_from` / `async_send_to`。

### 4.4 信令服务（SignalingService.h/.cpp）— ~200 行

```
HTTP API（仿 GatewayApp 的 HTTP 路由注册模式）:

POST /api/register    → 设备注册 + 更新 IP
POST /api/heartbeat   → 更新 last_seen + 超时自动下线
GET  /api/devices     → 返回在线设备列表 [{id,name,status,public_ip}]

POST /api/offer       → 存信令 map → WS 推送给目标设备
POST /api/answer      → 存信令 map → WS 推送给控制端
POST /api/ice         → WS 推送给对方

信令状态（内存存储，不落盘）:
  std::unordered_map<std::string, SignalingSession> sessions_;
  key = "ctrl_id:target_id"
```

### 4.5 WebSocket（WsSession.h/.cpp + WsSessionManager.h/.cpp）— ~250 行

基于 Boost.Beast 的 WebSocket 协议。仿 `ClientSession` 的模式：

```
WsSession (仿 ClientSession):
  Start()
    → async_accept()               # WebSocket 握手
    → DoRead()                      # async_read 循环
    → OnMessage(json_string)        # 解析 JSON → 处理
    → Send(json_string)             # async_write

WsSessionManager (仿 SessionManager):
  device_id → WsSession* 映射
  Register(device_id, session)
  Remove(device_id)
  SendToDevice(device_id, json)    # 推送到指定设备
```

## 5. 线程模型（复用 DemandStation 模式）

```
Main Thread (MainIO):
  io_context_
    ├── StunServer 事件（async_receive_from → async_send_to）
    ├── HTTP 请求回调（httplib 内部线程通过 post 投递）
    └── 信号处理（SIGINT → io_context_.stop()）

HttpIO Thread:
  httplib::Server::listen("0.0.0.0", 8080)   # 同步阻塞

Worker Threads (N=4，处理 WS 消息):
  WorkerIO_0 → io_context_0
    ├── WsSession (fd=3) 异步读写
    └── WsSession (fd=5)
  WorkerIO_1 → io_context_1
    ├── WsSession (fd=4)
    └── ...

Worker 的 thread_local SqlExec → SQLite 单连接（无锁）
```

**和 DemandStation 的区别**：没有 Redis（去掉 PaymentGateway 轮询）、没有 TcpServer（WebSocket 替代）、没有 MySQL（SQLite 替代）。但线程池模型完全一样。

## 6. 启动序列（仿 GatewayApp::Init + Start）

```
SignalingApp::Init():
  1. GlobalConfig::Init(cwd)          → 读 Config/server_config.json
  2. LogManager::Init("logs", level)  → Boost.Log
  3. SqliteDb::Init(db_path)          → 建表
  4. ThreadPool::Start(4)             → 4 个 Worker
  5. WsSessionManager::Init()
  6. SignalingService::Init()         → 注册 HTTP 路由
  7. StunServer::Init(io_context)     → 绑定 UDP :3478

SignalingApp::Start():
  1. tcp_acceptor (WS 端口)
  2. http_thread_ = thread(listen)    → httplib HTTP 服务器
  3. io_context_.run()                → 主事件循环
```
