# 第五阶段：抗丢包机制 — 详细实现设计

> 基于现有代码分析后的精确实现方案。当前系统已具备基础 UDP 视频收发能力，但完全无丢包恢复机制。

## 1. 现状分析与问题

### 1.1 当前丢包行为

```
服务端：VideoSender::SendFrame()
  → FragmentFrame(frame, frame_index, timestamp, is_keyframe)
  → for each packet: sendto(sock, packet, dest_addr)

客户端：VideoReceiver::ReceiveLoop()
  → recvfrom → NalReassembler::AddPacket()
  → 收到完整帧 → 放入 packet_queue → 解码
  → 丢包时：NalReassembler 收到下一帧 SOF 后，旧帧数据被覆盖丢弃
```

**问题**：
- 丢一个 UDP 包 → 整帧画面花屏（直到下一个 IDR 帧）
- 局域网丢包率通常 <0.1%，但 WiFi 或公网可达 1-5%
- 一个 IDR 帧通常 50-200KB，需要 36-143 个 UDP 包，任一丢失都花屏

### 1.2 当前协议包头

```cpp
#pragma pack(push, 1)
struct NalPacketHeader {
    uint8_t  flags;       // bit0=SOF, bit1=EOF, bit2=KEYFRAME
    uint16_t frame_index; // 帧序号
    uint16_t packet_index;// 帧内分片序号
    uint32_t timestamp;   // 时间戳(ms)
};
#pragma pack(pop)
// 总大小 = 9 字节，MAX_PAYLOAD_SIZE = 1400
```

### 1.3 已有基础设施

| 能力 | 状态 | 如何复用 |
|------|------|---------|
| `IVideoEncoder::EncodeFrame(texture, idx, force_idr, ...)` | ✅ 已有 | `force_idr=true` 即可产出 IDR |
| `ObsNvencEncoder::frame_->pict_type = AV_PICTURE_TYPE_I` | ✅ 已有 | FFmpeg 的 NVENC 封装直接支持 |
| TcpServer / InputTransport | ✅ 已有 | 客户端可通过控制信道发 IDR 请求 |
| SafeQueue | ✅ 已有 | 不需要改动 |
| NalReassembler（支持乱序） | ✅ 已有 | 需增加 FEC 恢复和丢包检测 |

## 2. 三档抗丢包策略

```
丢包量级       → 对策          → 恢复延迟
────────────────────────────────────────────
少量(1-2个/帧) → FEC 前向纠错  → 0ms（原地恢复）
中量(>FEC能力) → IDR 请求      → 1 RTT + 1帧编码时间
大量(>50%)    → IDR 请求      → 同上（等待下一帧）
```

**为什么不做 RFI（参考帧失效）**：
- RFI 需要直接调用 `nvEncInvalidateRefFrames`，FFmpeg 的 NVENC 封装不暴露此 API
- 当前编码器走 FFmpeg `h264_nvenc`，换直接调用 nvEncodeAPI 成本过大
- IDR 请求已经足够覆盖中大量丢包场景，RFI 的收益（用一个 P 帧代替 IDR）在当前阶段不是必须
- 后续如果需要 RFI，可以作为第六阶段编码器升级的子任务

## 3. 协议扩展：FEC 信息字段

### 3.1 扩展后的包头

```cpp
#pragma pack(push, 1)
struct NalPacketHeader {
    uint8_t  flags;         // bit0=SOF, bit1=EOF, bit2=KEYFRAME, bit3=FEC_PARITY
    uint16_t frame_index;   // 帧序号
    uint16_t packet_index;  // 帧内分片序号（数据包从 0 开始，校验包紧随其后）
    uint32_t timestamp;     // 时间戳(ms)
    uint8_t  fec_group_id;  // FEC 分组 ID（同一帧可能有多个 FEC 组）
    uint8_t  fec_data_count;// FEC 组内数据包数量
};
#pragma pack(pop)
// 总大小 = 11 字节（从 9 字节扩展 2 字节）
// MAX_PAYLOAD_SIZE = 1400（不变）
```
**新增字段说明**：

| 字段 | 大小 | 含义 |
|------|------|------|
| `flags bit3` | 1bit | `FLAG_FEC_PARITY`：标记此包为 FEC 校验包（非数据包） |
| `fec_group_id` | 1byte | 同一帧内 FEC 组编号（0, 1, 2...），数据包和校验包共享同一 group_id |
| `fec_data_count` | 1byte | FEC 组内数据包数量（校验包中填写，接收端据此判断组大小） |

**兼容性**：接收端通过 FLAG_FEC_PARITY 区分数据包和校验包。旧接收端不认识这个 flag，会正常处理数据包；校验包因没有 SOF/EOF 标记而被忽略（兼容）。

### 3.2 新增常量

```cpp
// ---- flags 扩展 ----
static constexpr uint8_t FLAG_FEC_PARITY = 0x08;   // FEC 校验包

// ---- NAL 包头大小更新 ----
static constexpr int NAL_HEADER_SIZE = 11;          // 原来 9，现在 11
static constexpr int FEC_HEADER_EXTRA = 2;          // 新增 2 字节

// ---- FEC 参数 ----
static constexpr int FEC_DATA_SHARDS = 5;           // 每组 5 个数据包
static constexpr int FEC_PARITY_SHARDS = 1;         // 每组 1 个校验包
static constexpr int FEC_TOTAL_SHARDS = 6;          // 5 + 1
static constexpr double FEC_OVERHEAD = 0.20;        // 20% 带宽开销

// ---- IDR 请求 ----
static constexpr int IDR_REQUEST_TIMEOUT_MS = 500;  // IDR 请求超时，超时后重发
static constexpr int MAX_CONSECUTIVE_LOST = 3;      // 连续丢失 3 帧触发 IDR 请求
```

### 3.3 包分类

```
一帧被 FragmentFrame 拆分为 N 个数据包 + M 个校验包：

帧数据 = [packet_0, packet_1, ..., packet_{N-1}]
         └── FEC group_0 ──┘ └── FEC group_1 ──┘ ...

每个 FEC 组最多包含 FEC_DATA_SHARDS=5 个数据包
最后一个组可能不满 5 个（通过 fec_data_count 记录）

对于每个 FEC 组：
  - 数据包：hdr.flags 正常，hdr.fec_group_id = group_idx
  - 校验包：hdr.flags |= FLAG_FEC_PARITY，hdr.fec_data_count = 组内数据包数
           hdr.packet_index = fec_data_count + parity_idx（从数据包序号后继续）
```

## 4. FEC 实现：XOR 前向纠错

### 4.1 为什么选 XOR 而非 Reed-Solomon

| 方面 | XOR | Reed-Solomon |
|------|-----|-------------|
| 复杂度 | ~50 行代码 | 需要引入 cm256 / nanors 库 |
| 恢复能力 | 每组恢复 1 个丢包 | 每组恢复 m 个丢包(1≤m≤parity) |
| 计算开销 | O(n)，GPU 可忽略 | GF(2^8) 矩阵运算，稍重 |
| 适用场景 | 丢包率 <2% | 丢包率 2-10% |
| 依赖 | 无（标准 C++） | 需引入第三方库 |

**决策**：XOR-based FEC，每组 5 数据 + 1 校验。在 2% 丢包率下：
- 6 包独立丢包概率：`1 - (1-0.02)^6 ≈ 11.4%` 的组至少丢 1 包
- 丢 ≥2 包概率：`1 - (1-0.02)^6 - 6*0.02*(1-0.02)^5 ≈ 0.5%` 的组无法恢复
- 即 99.5% 的丢包能被 FEC 原地恢复，0.5% 需要 IDR 请求兜底

后续如果需要更高恢复率，可以升级为 RS（n 数据 + 2 校验 → 可恢复 2 丢包）。

### 4.2 发送端：VideoSender 新增 FEC 编码

```cpp
// ---- 新增方法：对一帧的所有数据包生成 FEC 校验包 ----
static std::vector<std::vector<uint8_t>> GenerateFECParity(
    const std::vector<std::vector<uint8_t>>& data_packets,
    uint16_t frame_index,
    uint32_t timestamp,
    uint8_t fec_group_id,
    int fec_data_count)
{
    // 每个数据包大小可能不同（最后一个分片更小）
    // 取最大包大小作为校验包大小，短包尾补零参与计算
    size_t max_size = 0;
    for (const auto& p : data_packets)
        max_size = std::max(max_size, p.size());

    size_t parity_size = NAL_HEADER_SIZE + max_size - NAL_HEADER_SIZE;
    // 等价于：包头 + 最大负载大小（XOR 只对负载部分做，包头单独处理）

    // 1. 构建校验包 buffer
    std::vector<uint8_t> parity_packet(parity_size, 0);

    // 2. 填充包头
    NalPacketHeader hdr;
    hdr.flags = FLAG_FEC_PARITY;                    // 标记为校验包
    hdr.frame_index = frame_index;
    hdr.packet_index = data_packets.back()[1];      // 取最后一个数据包的 packet_index+1（实际在循环外算）
    hdr.timestamp = timestamp;
    hdr.fec_group_id = fec_group_id;
    hdr.fec_data_count = static_cast<uint8_t>(fec_data_count);
    std::memcpy(parity_packet.data(), &hdr, NAL_HEADER_SIZE);

    // 3. 对负载做 XOR（从 NAL_HEADER_SIZE 偏移开始）
    auto parity_payload = parity_packet.data() + NAL_HEADER_SIZE;
    auto payload_len = parity_size - NAL_HEADER_SIZE;

    for (const auto& dp : data_packets)
    {
        auto data_payload = dp.data() + NAL_HEADER_SIZE;
        auto data_len = dp.size() - NAL_HEADER_SIZE;

        for (size_t i = 0; i < data_len; ++i)
            parity_payload[i] ^= data_payload[i];
        // 短包尾部等价于 XOR 0，不变
    }

    return { parity_packet };
}
```

### 4.3 发送端：SendFrame 改造

```cpp
// 原 VideoSender::SendFrame 改造为：
void VideoSender::SendFrame(const uint8_t* frame_data, int frame_size,
                            uint16_t frame_index, uint32_t timestamp,
                            bool is_keyframe)
{
    // 1. 分片（不变）
    auto packets = FragmentFrame(frame_data, frame_size,
                                 frame_index, timestamp, is_keyframe);

    // 2. 填充 fec_group_id
    uint8_t group_id = 0;
    int packed_in_group = 0;
    int total_data_packets = (int)packets.size();

    // 3. 逐片发送数据包 + 每攒够 FEC_DATA_SHARDS 包就插入校验包
    // 用一个缓冲区收集当前组的数据包
    std::vector<std::vector<uint8_t>> group_buffer;

    for (int i = 0; i < total_data_packets; ++i)
    {
        // 填充 fec_group_id 到头（需要扩展 hdr.fec_group_id 字段）
        FillFecHeader(packets[i], group_id);
        group_buffer.push_back(packets[i]);
        packed_in_group++;

        if (packed_in_group >= FEC_DATA_SHARDS || i == total_data_packets - 1)
        {
            // 当前组已满或已是最后一组 → 生成校验包 + 发送全组
            int data_count = packed_in_group;

            // 生成校验包
            auto parity = GenerateFECParity(group_buffer, frame_index, timestamp,
                                            group_id, data_count);

            // 发送数据包
            for (const auto& dp : group_buffer)
                sendto(sock_, dp.data(), dp.size(), ...);

            // 发送校验包
            sendto(sock_, parity[0].data(), parity[0].size(), ...);

            // 重置
            group_buffer.clear();
            packed_in_group = 0;
            group_id++;
        }
    }
}
```

**关键点**：
- 原本一帧 N 个包，现在变成 `N + ceil(N/5)` 个包（20% 开销）
- 校验包放在组尾发送（不交织），简单可靠
- `fec_group_id` 从 0 递增，同一帧最多 256/5≈51 组，绰绰有余

### 4.4 接收端：NalReassembler 改造

```cpp
class NalReassembler
{
public:
    // 新增：AddPacket 改造，增加 FEC 识别
    bool AddPacket(const uint8_t* packet_data, int packet_size)
    {
        if (packet_size < NAL_HEADER_SIZE)
            return false;

        NalPacketHeader hdr;
        std::memcpy(&hdr, packet_data, NAL_HEADER_SIZE);

        // ---- 新增：FEC 校验包处理 ----
        if (hdr.flags & FLAG_FEC_PARITY)
        {
            // 不是数据包，是校验包。交给 FEC 恢复逻辑处理
            OnFecParityPacket(packet_data, packet_size, hdr);
            return false;  // 校验包不产生帧完成事件
        }

        // ---- 原有逻辑：处理数据包 ----
        // ...（原有 NalReassembler::AddPacket 逻辑不变）

        // 但在收到 EOF 后增加一步检查：
        if (hdr.flags & FLAG_EOF)
        {
            got_eof_ = true;

            // 检查是否所有分片都收到了
            if (HasMissingPackets())
            {
                // 有丢包 → 尝试 FEC 恢复
                if (!TryFecRecover(hdr))
                {
                    // FEC 恢复失败 → 记录丢帧统计
                    lost_frames_++;
                    packet_map_.clear();
                    return false;
                }
            }

            // 拼帧（原有逻辑）
            frame_buffer_.clear();
            for (const auto& pair : packet_map_)
                frame_buffer_.insert(..., pair.second...);

            packet_map_.clear();
            // ... 返回 true
        }
        // ...
    }

private:
    // FEC 恢复状态
    struct FecGroupState
    {
        uint16_t frame_index;
        uint8_t  group_id;
        int      data_count;                             // 组内数据包数量
        int      received_count;                         // 已收到数据包数
        std::vector<uint8_t> parity_packet;              // 校验包数据
        bool     parity_received;
        int      missing_index;                          // 缺失的那个包的 packet_index（-1=不缺）
    };
    std::map<std::pair<uint16_t, uint8_t>, FecGroupState> fec_groups_;

    // FEC 统计
    int fec_recovered_{0};                               // FEC 恢复成功次数
    int lost_frames_{0};                                 // 无法恢复的丢帧次数

    // 处理 FEC 校验包
    void OnFecParityPacket(const uint8_t* data, int size, const NalPacketHeader& hdr)
    {
        auto key = std::make_pair(hdr.frame_index, hdr.fec_group_id);
        auto& state = fec_groups_[key];
        state.frame_index = hdr.frame_index;
        state.group_id = hdr.fec_group_id;
        state.data_count = hdr.fec_data_count;
        state.parity_packet.assign(data, data + size);
        state.parity_received = true;
    }

    // 在组帧完成时更新收到的数据包计数
    void OnDataPacketReceived(const NalPacketHeader& hdr)
    {
        auto key = std::make_pair(hdr.frame_index, hdr.fec_group_id);
        auto& state = fec_groups_[key];
        state.received_count++;
    }

    // 检查当前帧是否有缺失分片
    bool HasMissingPackets()
    {
        if (packet_map_.empty()) return false;
        int max_index = packet_map_.rbegin()->first;  // 最大 packet_index
        return (int)packet_map_.size() <= max_index;  // 有空洞
    }

    // 尝试 FEC 恢复
    bool TryFecRecover(const NalPacketHeader& eof_hdr)
    {
        auto key = std::make_pair(eof_hdr.frame_index, eof_hdr.fec_group_id);
        auto it = fec_groups_.find(key);
        if (it == fec_groups_.end() || !it->second.parity_received)
            return false;                               // 没有校验包，无法恢复

        auto& state = it->second;

        // 找出缺失的 packet_index
        int min_idx = packet_map_.begin()->first;
        int max_idx = packet_map_.rbegin()->first;
        int missing_idx = -1;
        for (int i = min_idx; i <= max_idx; ++i)
        {
            if (packet_map_.find(i) == packet_map_.end())
            {
                if (missing_idx == -1)
                    missing_idx = i;
                else
                    return false;                       // 缺 >1 个包，XOR 无法恢复
            }
        }

        if (missing_idx == -1)
            return false;                               // 不缺包（不应该到这里）

        // XOR 恢复：missing = parity XOR sum_of_received
        auto& parity = state.parity_packet;
        size_t payload_offset = NAL_HEADER_SIZE;
        size_t payload_len = parity.size() - NAL_HEADER_SIZE;

        std::vector<uint8_t> recovered_payload(payload_len, 0);
        std::memcpy(recovered_payload.data(), parity.data() + payload_offset, payload_len);

        for (const auto& [idx, data] : packet_map_)
        {
            size_t dp_len = data.size() - NAL_HEADER_SIZE;
            for (size_t i = 0; i < dp_len; ++i)
                recovered_payload[i] ^= data[i];
        }

        // 构建恢复后的完整包（包头 + 恢复的负载）
        // 需要伪造一个正常的包头填入 packet_map_
        NalPacketHeader recovered_hdr;
        std::memcpy(&recovered_hdr, parity.data(), NAL_HEADER_SIZE);
        recovered_hdr.flags &= ~FLAG_FEC_PARITY;        // 去掉 FEC 标记
        recovered_hdr.packet_index = static_cast<uint16_t>(missing_idx);

        // 根据位置设置 SOF/EOF
        if (missing_idx == min_idx)
            recovered_hdr.flags |= FLAG_SOF;
        if (missing_idx == max_idx)
            recovered_hdr.flags |= FLAG_EOF;

        std::vector<uint8_t> recovered_packet(payload_offset + payload_len);
        std::memcpy(recovered_packet.data(), &recovered_hdr, NAL_HEADER_SIZE);
        std::memcpy(recovered_packet.data() + NAL_HEADER_SIZE,
                    recovered_payload.data(), payload_len);

        packet_map_[missing_idx] = std::move(recovered_packet);
        fec_recovered_++;
        return true;
    }
};
```

**注意**：FEC 恢复逻辑在 `AddPacket` 收到 EOF 后触发，此时当前帧所有数据包和校验包都应该已到达（或已丢失）。恢复成功后 `packet_map_` 变为完整，继续走正常的拼帧流程。

## 5. 丢包检测与 IDR 请求

### 5.1 客户端丢包统计

在 `VideoReceiver::ReceiveLoop` 中增加丢包统计：

```cpp
// 新增成员变量
uint16_t expected_frame_index_{0};    // 期望的下一个 frame_index
int consecutive_lost_frames_{0};      // 连续丢失的帧数
int total_lost_frames_{0};            // 总丢帧数
int fec_recovered_frames_{0};         // FEC 恢复的帧数（从 NalReassembler 读取）

// ReceiveLoop 中，每收到一个完整帧后：
uint16_t current_frame = reassembler_.GetFrameIndex();
if (expected_frame_index_ != 0 && current_frame != expected_frame_index_)
{
    // 跳帧 = 丢帧
    uint16_t skipped = (current_frame - expected_frame_index_) & 0xFFFF;
    total_lost_frames_ += skipped;
    consecutive_lost_frames_++;
}
else
{
    consecutive_lost_frames_ = 0;
}
expected_frame_index_ = (current_frame + 1) & 0xFFFF;
```

```cpp

```

### 5.5 为什么需要降频

IDR 帧比 P 帧大 5-10 倍（完整 I 帧 vs 差分帧），频繁 IDR 请求会瞬间消耗大量带宽。增加防抖：

```cpp
// 两次 IDR 请求之间至少间隔 500ms
if (now - last_idr_request_time_ < std::chrono::milliseconds(500))
    return;  // 跳过，不重复请求
```

- `NalReassembler` 结构不变（FEC 逻辑内嵌在 AddPacket 内，接口不变）
- `VideoDecoder`、`VideoRenderer` 不感知 FEC

## 7. 实现顺序

```
步骤 1：协议扩展（NalUnit.h）
  ├── 扩 NAL_HEADER_SIZE 9→11
  ├── 新增 FLAG_FEC_PARITY
  ├── 新增 fec_group_id、fec_data_count 字段
  └── 更新自测函数

步骤 2：FEC 发送端（VideoSender）
  ├── 实现 GenerateFECParity()
  ├── 改造 SendFrame()：分组编码 + 插入校验包
  └── 本地环回验证：检查校验包数 = ceil(数据包数/5)

步骤 3：FEC 接收端（NalReassembler）
  ├── AddPacket 增加校验包处理
  ├── 实现 OnFecParityPacket()、TryFecRecover()
  └── 增加 fec_recovered_ 统计

步骤 4：丢包统计（VideoReceiver）
  ├── 增加 frame_index 连续性检测
  ├── 增加 consecutive_lost_frames_ 计数
  └── 增加 total_lost_frames_、fec_recovered_frames_ 日志输出

步骤 5：IDR 请求
  ├── 客户端：consecutive_lost >= 3 时通过控制信道发送 JSON
  ├── 服务端：InputTransport 解析 request_idr → 置 force_next_idr_
  ├── StreamServer::Run() 读取 force_next_idr_
  └── 防抖：500ms 内不重复请求

步骤 6：集成测试
  ├── 正常网络：验证 FEC 校验包数正确
  ├── Clumsy 5% 丢包：验证 FEC 恢复 >90% 丢包
  ├── Clumsy 20% 丢包：验证 IDR 请求触发
  └── 长时间丢包：验证不永久花屏
```

|------|------|
