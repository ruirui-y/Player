## 第一步：软解 + QWindow 渲染（看到画面）

这是最重要的里程碑，证明整个链路通了。后面的所有工作都基于这一步。

### 1.1 梳理 FFmpegCore 需要什么东西

你之前列的头文件成员是齐全的，但按第一步的需求，可以先精简，不需要音频相关的东西。第一步只需要：

**成员变量：**
- `AVFormatContext* fmt_ctx_` — 解封装上下文
- `AVCodecContext* codec_ctx_` — 视频解码器上下文
- `int video_stream_idx_` — 视频流索引
- `std::atomic<bool> playing_` — 播放状态
- `std::atomic<bool> paused_` — 暂停状态
- `std::thread decode_thread_` — 解码线程
- `QTimer* progress_timer_` — 进度定时器（后面用，第一步可以先不搞）
- `QWindow* video_surface_` — 视频渲染窗口

**公开方法：**
- `bool OpenFile(const QString& path)` — 打开文件
- `void Play()` — 开始播放
- `void Pause()` — 暂停
- `void Stop()` — 停止
- `void Close()` — 关闭释放

### 1.2 OpenFile 的实现思路

OpenFile 只做一件事：把文件打开，找到视频流，准备好解码器。不启动解码线程。

**顺序是这样的：**

**第 1 小步：avformat_open_input**
- 用 `avformat_open_input(&fmt_ctx_, path, nullptr, nullptr)` 打开文件
- 如果失败，发射 SigError 然后返回 false

**第 2 小步：avformat_find_stream_info**
- 用 `avformat_find_stream_info(fmt_ctx_, nullptr)` 获取流信息
- 这一步之后 fmt_ctx_->streams 里才有内容

**第 3 小步：找到视频流**
- 遍历 fmt_ctx_->streams，找到 `stream->codecpar->codec_type == AVMEDIA_TYPE_VIDEO` 的那个
- 记录它的索引到 video_stream_idx_，保留它的 codecpar

**第 4 小步：打开解码器**
- `avcodec_find_decoder(codecpar->codec_id)` 找到解码器
- `avcodec_alloc_context3(codec)` 分配解码器上下文
- `avcodec_parameters_to_context(codec_ctx_, codecpar)` 把流参数填充进去
- `avcodec_open2(codec_ctx_, codec, nullptr)` 打开解码器

**第 5 小步：记录总时长**
- `duration_ms_ = fmt_ctx_->duration / AV_TIME_BASE * 1000`
- 注意 fmt_ctx_->duration 的单位是 AV_TIME_BASE（微秒）

**第 6 小步：发射 loaded 回调**

- 发射 SigLoaded(duration_ms_)，通知控制端文件加载完成，可以播放了

### 1.3 Play 的实现思路

Play 要做两件事：
1. 设置 playing_ = true
2. 启动 decode_thread_

**解码线程 decode_thread_ 的循环逻辑：**

```c++
while (playing_)
{
    if (paused_)
    {
        Sleep(10);  // 暂停时歇一下，不空转
        continue;
    }

    // 读一个包
    AVPacket* packet = av_packet_alloc();
    int ret = av_read_frame(fmt_ctx_, packet);

    if (ret < 0)
    {
        // 读完了或者出错
        if (ret == AVERROR_EOF)
        {
            // 文件播放完毕
            emit SigFinished();
        }
        break;
    }

    // 只处理视频包
    if (packet->stream_index == video_stream_idx_)
    {
        // 把包送给解码器
        avcodec_send_packet(codec_ctx_, packet);

        AVFrame* frame = av_frame_alloc();
        int ret2 = avcodec_receive_frame(codec_ctx_, frame);

        if (ret2 == 0)
        {
            // 成功解码出一帧
            // 计算当前 PTS（毫秒）
            if (frame->pts != AV_NOPTS_VALUE)
            {
                AVRational tb = fmt_ctx_->streams[video_stream_idx_]->time_base;
                int64_t pts_ms = frame->pts * av_q2d(tb) * 1000;
                current_pts_ms_ = pts_ms;
            }

            // 渲染这一帧（后面讲怎么渲染）
            RenderFrame(frame);
        }

        av_frame_free(&frame);
    }

    av_packet_free(&packet);
}
```

**几个关键点：**

**为什么只处理视频包？**
当前第一步只做视频，音频包直接丢弃（av_packet_free）。音频后面第四步再加。

**为什么 av_read_frame 读出来还要判断 stream_index？**
因为 av_read_frame 会把文件里所有类型的包都读出来（视频、音频、字幕），你得只拿你要的。

**为什么要算 PTS？**
PTS 是这一帧在时间轴上的位置，单位是 time_base。不同文件的 time_base 不一样，所以要乘一下转成毫秒。后面进度上报、seek 都要靠它。

### 1.4 软解渲染的实现思路（临时方案）

第一步先用最笨的办法把画面画出来：把 AVFrame 转成 QImage，然后用 QPainter 画到 QWindow 上。

**为什么说是临时方案？**
因为 sws_scale 走的是 CPU，4K 以上就会卡。但第一步只看能不能通，不追求性能。

**具体做法：**

在 FFmpegCore 里加一个 RenderFrame(AVFrame* frame) 方法：

```c++
void FFmpegCore::RenderFrame(AVFrame* frame)
{
    // 1. 如果还没有创建转换上下文，就创建一个
    if (sws_ctx_ == nullptr)
    {
        sws_ctx_ = sws_getContext(
            frame->width, frame->height, (AVPixelFormat)frame->format,  // 源格式
            frame->width, frame->height, AV_PIX_FMT_RGB24,              // 目标格式
            SWS_BILINEAR, nullptr, nullptr, nullptr);
    }

    // 2. 分配一个 RGB 缓冲区
    // 这里可以复用缓冲区，不用每帧都 new/delete

    // 3. sws_scale 转换
    uint8_t* rgb_data = ...;
    int rgb_linesize = frame->width * 3;
    sws_scale(sws_ctx_,
              frame->data, frame->linesize, 0, frame->height,
              &rgb_data, &rgb_linesize);

    // 4. 用 rgb_data 创建 QImage
    QImage image(rgb_data, frame->width, frame->height, QImage::Format_RGB888);

    // 5. 关键：把 QImage 画到 video_surface_ 上
    // 这一步不能直接画，因为 QWindow 没有 paintEvent
    // 怎么做？见下面的详细说明
}
```

**把 QImage 画到 QWindow 上的做法：**

QWindow 本身不能直接 paint。有两种做法：

**做法 A（推荐给第一步）：在 MainWindow 里放一个 QWidget**
- MainWindow 本身是 QMainWindow，它里面放一个 centralWidget
- 在这个 centralWidget 里放一个 QLabel 或者重写 QWidget 的 paintEvent
- FFmpegCore 解码出 QImage 后，通过信号槽发到主线程，让 QWidget 显示

具体怎么做：
1. 在 MainWindow.h 里加一个 `QWidget* video_widget_`，并重写它的 paintEvent（或者直接用 QLabel）
2. FFmpegCore 加一个信号 `SigFrameReady(QImage image)`
3. 在解码线程里 emit SigFrameReady(image)，但因为跨线程，Qt 会自动用队列连接
4. MainWindow 的槽函数里调用 `video_widget_->setPixmap(QPixmap::fromImage(image))` 或者 update() 后在 paintEvent 里 drawImage

**注意：** QImage 是在解码线程里创建的，emit 信号时 Qt 会（默认用队列连接）把 QImage 拷贝到主线程。这一步开销不小，但第一步可以接受。

**做法 B（更正确但更复杂）：直接用 QWindow 的 renderEngine**

- 继承 QWindow 并重写 exposeEvent / render
- 用 QPainter 直接画在 QWindow 上
- 但 QWindow 是底层窗口，画起来比较麻烦，建议先做法 A

**所以第一步的结构变成：**

```
解码线程 → AVFrame → sws_scale → QImage → 信号 SigFrameReady → MainWindow 槽 → QWidget::setPixmap 显示
```

虽然慢，但通。

### 1.5 Pause 和 Stop 的实现思路

**Pause：**
- `paused_ = true`
- 解码线程检测到 paused_ 后进入 sleep 循环
- 发射 SigPlayState("paused")

**Stop：**
- `playing_ = false`（解码线程会退出循环）
- 如果解码线程 joinable，join 等它退出
- 调用 `avcodec_flush_buffers(codec_ctx_)` 清空解码器缓存
- 复位当前 PTS（current_pts_ms_ = 0）
- 发射 SigPlayState("stopped")
- **重要：不要关闭 fmt_ctx_ 和 codec_ctx_**，因为 Stop 之后可能还会 Play 重新播放同一个文件
- 要重新播放同一个文件：在 Play 里调用 `av_seek_frame(fmt_ctx_, video_stream_idx_, 0, AVSEEK_FLAG_BACKWARD)` 回到开头

### 1.6 验证方法

做完这一步，你应该能：

1. 写一个临时 main.cpp 测试代码，harcode 一个视频路径
2. 程序启动后自动打开文件，自动播放
3. 能看到视频画面出现在指定位置
4. 调用 Pause 画面停止，调用 Play 继续，调用 Stop 回到开头

**如果画面出不来，排查顺序：**
- ffprobe 看视频文件格式是否支持
- av_open_input 返回值是不是 0
- avcodec_find_decoder 有没有找到解码器
- avcodec_receive_frame 能不能拿到 frame
- frame 的宽高是不是正常的

## 第二步：硬解 + 直接渲染（性能达标）

第一步用的是 sws_scale（CPU 转 RGB）+ QImage 传输（主线程拷贝），这一步要把它替换成 D3D11 硬解（GPU 解码）+ 直接纹理拷贝（GPU 到显存）。

### 2.1 为什么硬解能解决性能问题

软解的瓶颈在两个地方：
- **解码本身**：CPU 要算 H.264/H.265 的熵编码、运动补偿、环路滤波，4K 以上 CPU 就吃满了
- **sws_scale 转 RGB**：YUV 转 RGB 是像素级的运算，大量 cache miss，非常慢
- **QImage 跨线程传递**：把 GPU 里的数据读回 CPU 内存，再通过 Qt 的队列拷贝一次，延迟和带宽都是问题

硬解方案：
- 解码在 GPU 上完成，解码后的帧直接是 D3D11 的 texture（GPU 显存里），不需要从显存拷回内存
- 渲染时直接把 texture 拷贝到交换链（也在显存里），全程不走 CPU
- CPU 占用从 80%+ 降到 5% 以下

### 2.2 需要引入 D3D11

FFmpeg 的 D3D11VA 硬解不会自动帮你创建 D3D11 设备和交换链。你需要自己管理：

**两个关键对象：**
- `ID3D11Device` — D3D11 设备，负责创建纹理、buffer 等
- `ID3D11DeviceContext` — 设备上下文，负责执行拷贝、渲染命令

**怎么创建：**
```
// 创建一个 D3D11 设备和上下文
D3D11CreateDevice(
    nullptr,                     // 使用默认适配器（当前显卡）
    D3D_DRIVER_TYPE_HARDWARE,   // 硬件加速
    nullptr,                     // 不指定软件驱动
    D3D11_CREATE_DEVICE_VIDEO_SUPPORT,  // 需要视频支持
    featureLevels,               // 特性级别列表
    ARRAYSIZE(featureLevels),
    D3D11_SDK_VERSION,
    &d3d11_device_,
    &selected_feature_level,
    &d3d11_device_ctx_
);
```

注意 `D3D11_CREATE_DEVICE_VIDEO_SUPPORT` 这个 flag，没有它就用不了 D3D11VA 硬解。

### 2.3 把硬解集成到 OpenFile 里

在第一步的 OpenFile 流程中，找到解码器之后、avcodec_open2 之前，插入硬解初始化：

```
// 1. 找到 D3D11VA 硬件设备类型
AVHWDeviceType hw_type = av_hwdevice_find_type_by_name("d3d11va");

// 2. 创建硬件设备上下文
// 注意：这里需要把 d3d11_device_ 传进去，而不是让 FFmpeg 自己创建
// 因为你要用同一个设备做解码和渲染
AVBufferRef* hw_device_ctx = av_hwdevice_ctx_alloc(AV_HWDEVICE_TYPE_D3D11VA);
AVHWDeviceContext* device_ctx = (AVHWDeviceContext*)hw_device_ctx->data;
AVD3D11VADeviceContext* d3d11va_ctx = (AVD3D11VADeviceContext*)device_ctx->hwctx;
d3d11va_ctx->device = d3d11_device_;  // 传入你自己创建的 D3D11 设备

// 3. 初始化硬件设备上下文
av_hwdevice_ctx_init(hw_device_ctx);
hw_device_ctx_ = hw_device_ctx;

// 4. 把硬件设备上下文赋给 codec_ctx
codec_ctx_->hw_device_ctx = av_buffer_ref(hw_device_ctx_);

// 5. 设置 codec_ctx_->get_format 回调
// 在回调里返回硬解码像素格式
```

**为什么 codec_ctx_->get_format 回调这么重要？**

解码器在打开的时候会调用这个回调，问你"我要用什么像素格式解码"。你要返回 `AV_PIX_FMT_D3D11VA`，解码器才会启用硬解。如果不设这个回调，解码器默认用软解。

回调示例：
```
static AVPixelFormat get_hw_format(AVCodecContext* ctx, const AVPixelFormat* pix_fmts)
{
    const AVPixelFormat* p;
    for (p = pix_fmts; *p != AV_PIX_FMT_NONE; p++)
    {
        if (*p == AV_PIX_FMT_D3D11VA)
            return *p;
    }
    return pix_fmts[0];  // 不支持硬解，回退到第一个格式
}
```

### 2.4 创建交换链（用于显示）

你需要在视频渲染窗口（QWindow）上创建一个交换链，这样解码出来的纹理才能显示出来。

```
// 拿到 QWindow 的 HWND
HWND hwnd = (HWND)video_surface_->winId();

// 创建交换链
DXGI_SWAP_CHAIN_DESC scd = {0};
scd.BufferCount = 2;                   // 双缓冲
scd.BufferDesc.Width = width;
scd.BufferDesc.Height = height;
scd.BufferDesc.Format = DXGI_FORMAT_B8G8R8A8_UNORM;
scd.BufferUsage = DXGI_USAGE_RENDER_TARGET_OUTPUT;
scd.OutputWindow = hwnd;
scd.SampleDesc.Count = 1;
scd.Windowed = TRUE;

IDXGIDevice* dxgi_device = nullptr;
d3d11_device_->QueryInterface(__uuidof(IDXGIDevice), (void**)&dxgi_device);
IDXGIAdapter* dxgi_adapter = nullptr;
dxgi_device->GetAdapter(&dxgi_adapter);
IDXGIFactory* dxgi_factory = nullptr;
dxgi_adapter->GetParent(__uuidof(IDXGIFactory), (void**)&dxgi_factory);

dxgi_factory->CreateSwapChain(d3d11_device_, &scd, &swapchain_);
```

### 2.5 硬解渲染流程（替换第一步的 sws_scale + QImage）

解码线程解码出 AVFrame 后，先检查它的格式：

```
if (frame->format == AV_PIX_FMT_D3D11VA)
{
    // 硬解帧
    // 1. 拿到 D3D11 texture
    AVHWFramesContext* hw_frame_ctx = (AVHWFramesContext*)frame->hw_frames_ctx->data;
    AVD3D11VAFrame* d3d11_frame = (AVD3D11VAFrame*)frame->data[0];
    ID3D11Texture2D* decoder_texture = (ID3D11Texture2D*)d3d11_frame->texture;

    // 2. 从交换链拿后台缓冲区
    ID3D11Texture2D* backbuffer = nullptr;
    swapchain_->GetBuffer(0, __uuidof(ID3D11Texture2D), (void**)&backbuffer);

    // 3. 从解码纹理拷贝到后台缓冲区
    d3d11_device_ctx_->CopyResource(backbuffer, decoder_texture);

    // 4. Present 显示
    swapchain_->Present(0, 0);

    // 5. 释放引用
    backbuffer->Release();
}
else
{
    // 软解帧，用第一步的 sws_scale 方案
}
```

**关键点：为什么 CopyResource 就能显示，不需要 shader？**

因为解码器解码出来的 texture 格式跟交换链的后台缓冲区格式都是 DXGI_FORMAT_NV12 或类似格式，并且都在 GPU 显存里。CopyResource 是 GPU 内部的拷贝，不经过 CPU，速度极快。交换链 Present 的时候 GPU 会自动把 NV12 转换成显示需要的 RGB 格式（这叫 VPBLL Display 模式）。

### 2.6 画面位置控制

MainWindow 里实现 SetVideoRect：

```
void MainWindow::SetVideoRect(int x, int y, int w, int h)
{
    // 设置主窗口几何
    setGeometry(x, y, w, h);

    // 如果 video_widget_ 存在，也调整它的大小填满窗口
    if (video_widget_)
        video_widget_->setGeometry(0, 0, w, h);
}
```

注意：窗口隐藏后 setGeometry 是否生效？

答案是生效的。QWindow::setGeometry 即使窗口不可见，也会正确记录位置和尺寸。当你在 D3D11 CreateSwapChain 时用这个窗口的 HWND，交换链会绑定到这个窗口的位置上。即使窗口不可见，D3D11 的 Present 依然会把画面输出到显示器上。

**等一下，窗口隐藏了 Present 还能显示？**
- 如果窗口用 `setWindowFlags(Qt::Tool | Qt::FramelessWindowHint)` 但不设置父窗口，它虽然不显示在任务栏，但窗口本身是存在的
- 解决办法：把窗口设置为**透明窗口**，背景完全透明，只显示视频画面
- 或者更直接的做法：窗口设置为 `WS_EX_LAYERED | WS_EX_TRANSPARENT` 扩展样式，这样窗口本身不显示，但 D3D11 渲染的内容会穿透出来
- 这一步比较复杂，建议到第五步再做，第一步先让窗口正常显示

## 第三步：TCP 服务器（能通过指令控制）

前面两步你已经能本地播放了。这一步加上网络控制。

### 3.1 TcpServer 的设计

**类职责：**
- 监听 TCP 端口
- 接收控制端连接
- 解析 JSON 指令，发射对应的信号
- 把回调事件打包成 JSON 发回控制端

**几个核心逻辑：**

**只接受一个客户端：**
```
void TcpServer::OnNewConnection()
{
    while (server_->hasPendingConnections())
    {
        QTcpSocket* new_client = server_->nextPendingConnection();

        // 如果已有客户端，断开旧的（或拒绝新的，看你选择）
        if (client_ && client_->state() == QAbstractSocket::ConnectedState)
        {
            new_client->disconnectFromHost();  // 拒绝新连接
            new_client->deleteLater();
            continue;
        }

        client_ = new_client;
        connect(client_, &QTcpSocket::readyRead, this, &TcpServer::OnReadyRead);
        connect(client_, &QTcpSocket::disconnected, this, &TcpServer::OnClientDisconnected);
    }
}
```

**JSON 解析：**
```
void TcpServer::OnReadyRead()
{
    QByteArray data = client_->readAll();

    // 因为 TCP 是流式协议，可能一次 recv 只收到半条指令
    // 所以要用一个 buffer 缓存
    buffer_.append(data);

    // 尝试解析 buffer 里的内容
    // 每次解析一条完整的 JSON 对象（用大括号匹配）
    // 解析成功就处理，剩下的留在 buffer_ 里下次再处理
}
```

**TCP 粘包处理：**
TCP 不保证一次 recv 正好是一条消息。可能一次收到多条，也可能一条分两次收到。

处理方法：
- 维护一个 QByteArray buffer_
- 每次收到数据先 append 到 buffer_
- 尝试从 buffer_ 里提取完整的 JSON 字符串（用 { } 匹配）
- 提取成功一条就处理一条，处理完后把这条从 buffer_ 删掉
- 继续尝试提取下一条，直到 buffer_ 里没有完整 JSON

### 3.2 指令解析 -> 信号映射

收到一条 JSON 后：

```
{"cmd":"open","data":{"path":"D:\\video.mp4"}}
{"cmd":"play","data":{}}
{"cmd":"pause","data":{}}
{"cmd":"stop","data":{}}
{"cmd":"exit","data":{}}
```

解析流程：
1. QJsonDocument::fromJson 解析
2. 取根对象的 "cmd" 字段，判断是什么指令
3. 取 "data" 字段，提取参数
4. 发射对应的信号

映射表：

| cmd 字符串 | 发射信号                 |
| ---------- | ------------------------ |
| open       | SigOpen(path)            |
| play       | SigPlay()                |
| pause      | SigPause()               |
| stop       | SigStop()                |
| exit       | SigExit()                |
| volume     | SigVolume(vol)           |
| seek       | SigSeek(pos_ms)          |
| set_window | SigSetWindow(x, y, w, h) |

### 3.3 回调发送

回调格式：

```
{"event":"loaded","data":{"duration_ms":120000}}
{"event":"progress","data":{"pos_ms":15000,"duration_ms":120000}}
{"event":"finished","data":{}}
{"event":"error","data":{"msg":"..."}}
{"event":"play_state","data":{"state":"playing"}}
```

实现方式：
```
void TcpServer::SendEvent(const QString& event_name, const QJsonObject& data)
{
    if (!client_ || client_->state() != QAbstractSocket::ConnectedState)
        return;  // 没有控制端连接，直接丢弃

    QJsonObject root;
    root["event"] = event_name;
    root["data"] = data;

    QByteArray json = QJsonDocument(root).toJson(QJsonDocument::Compact);
    json.append("\n");  // 每条消息以换行结尾，方便控制端解析

    client_->write(json);
    client_->flush();
}
```

**为什么每条 JSON 后面加换行？**
控制端也面临 TCP 粘包问题，用换行符分割是 TCP JSON 协议最常用的做法。控制端按行读取就能拿到每条完整的消息。

### 3.4 进度 QTimer

进度上报不放在 FFmpegCore 里，由 main.cpp 协调。

为什么：进度上报是一个"主动轮询"行为，FFmpegCore 只负责提供 current_pts_ms_ 这个值，不负责主动推。谁想读进度谁自己定时间隔。

```
// 在 main.cpp 里：
QTimer* progress_timer = new QTimer(&app);
connect(progress_timer, &QTimer::timeout, [&]() {
    if (player.IsPlaying())  // 只在播放时上报
    {
        qint64 pos = player.GetPosition();  // 读 current_pts_ms_
        qint64 dur = player.GetDuration();
        QJsonObject data;
        data["pos_ms"] = pos;
        data["duration_ms"] = dur;
        server.SendEvent("progress", data);
    }
});
progress_timer->start(500);
```

1. 启动程序
2. 用网络调试工具（如 NetAssist、SocketTool 或直接写一个 Python 脚本）连接 TCP 端口
3. 发送 JSON 指令，看播放器响应
4. 观察回调消息是否正常收到

## 第四步：音频播放

前几步只有画面没有声音。这一步加上。

### 4.1 需要新增的东西

**新的成员变量：**
- `int audio_stream_idx_` — 音频流索引
- `AVCodecContext* audio_codec_ctx_` — 音频解码器上下文
- `SwrContext* swr_ctx_` — 音频重采样上下文（把 AVFrame 转成 PCM）
- `QAudioSink* audio_sink_` — Qt 音频输出设备
- `QIODevice* audio_io_device_` — 音频输出设备的 I/O 通道
- `std::queue<QByteArray> audio_queue_` — 音频 PCM 数据队列
- `std::mutex audio_mutex_` — 队列的线程锁
- `std::thread audio_thread_` — 音频播放线程

### 4.2 OpenFile 里增加音频解码器初始化

在第一步的 OpenFile 流程中，找到视频流之后，再找音频流：

```
for (int i = 0; i < fmt_ctx_->nb_streams; i++)
{
    if (fmt_ctx_->streams[i]->codecpar->codec_type == AVMEDIA_TYPE_AUDIO)
    {
        audio_stream_idx_ = i;
        // 打开音频解码器（跟视频解码器类似）
        // ...
        break;
    }
}
```

音频解码器不需要硬解，CPU 解码音频压力很小（一个 8K 视频的音频可能只有几百 kbps）。

### 4.3 解码线程里添加音频处理

在 av_read_frame 循环里，除了处理视频包，还要处理音频包：

```
if (packet->stream_index == audio_stream_idx_)
{
    avcodec_send_packet(audio_codec_ctx_, packet);

    AVFrame* frame = av_frame_alloc();
    int ret = avcodec_receive_frame(audio_codec_ctx_, frame);

    if (ret == 0)
    {
        // 把 AVFrame 转成 PCM 数据
        // 用 swr_convert 把 AVFrame 的原始格式转成
        // 16位整型 + 44100/48000 采样率 + 立体声
        uint8_t* pcm_data = ...;
        int pcm_size = ...;

        // 把 PCM 数据放到音频队列里
        {
            std::lock_guard<std::mutex> lock(audio_mutex_);
            audio_queue_.push(QByteArray((char*)pcm_data, pcm_size));
        }
    }

    av_frame_free(&frame);
}
```

### 4.4 音频播放线程

音频播放线程单独跑，从队列里取 PCM 数据，喂给 QAudioSink：

```
void FFmpegCore::AudioThreadFunc()
{
    // 创建 QAudioSink
    // 注意：QAudioSink 必须在主线程创建（Qt 的音频后端要求），所以不能在解码线程里创建
    // 做法：在 Play() 里发射一个信号，让 main.cpp 在主线程创建 QAudioSink

    QAudioFormat format;
    format.setSampleRate(48000);
    format.setChannelCount(2);
    format.setSampleSize(16);
    format.setCodec("audio/pcm");
    format.setByteOrder(QAudioFormat::LittleEndian);
    format.setSampleType(QAudioFormat::SignedInt);

    audio_sink_ = new QAudioSink(format, nullptr);
    audio_io_device_ = audio_sink_->start();  // 开始播放

    while (playing_)
    {
        QByteArray pcm_data;
        {
            std::lock_guard<std::mutex> lock(audio_mutex_);
            if (!audio_queue_.empty())
            {
                pcm_data = audio_queue_.front();
                audio_queue_.pop();
            }
        }

        if (!pcm_data.isEmpty())
        {
            audio_io_device_->write(pcm_data);
        }
        else
        {
            // 队列空了，等一下
            Sleep(10);
        }
    }
}
```

但这里有一个问题：QAudioSink 不能在子线程创建。解决办法：

1. FFmpegCore 发射 SigNeedAudioOutput(format) 信号
2. 这个信号连接到 main.cpp 的一个 lambda，在主线程创建 QAudioSink
3. 把创建好的 QAudioSink 和 QIODevice 传回给 FFmpegCore

或者更简单：在 main.cpp 里提前创建好 QAudioSink，解码线程往 QIODevice 里写就行（QIODevice::write 是线程安全的）。

### 4.5 A/V 同步

有了音频之后，视频不能无脑播放了，必须跟音频对齐。

**A/V 同步的基本原理：**

- 音频按照采样率节奏自己播放，天然有"时钟"（audio clock）
- 视频要跟着音频走：当前帧的 PTS 跟 audio clock 比较
  - 如果 PTS > audio clock → 帧来早了 → 等一会儿再显示
  - 如果 PTS < audio clock → 帧来晚了 → 直接丢掉

**具体实现：**

在解码线程里维护一个 audio_clock（通过已经喂给 QAudioSink 的 PCM 数据量计算）：

```
// 计算 audio clock（当前正在播放的位置）
double FFmpegCore::GetAudioClock()
{
    // 已经写入音频设备的总样本数 / 采样率 * 1000（毫秒）
    // 减去 QAudioSink 已经播放但还没完成的缓冲区大小
    // 这个计算稍复杂，简化版直接用"解码出的音频帧的 PTS"做参考
}
```

视频帧显示时：
```
if (frame->pts * av_q2d(time_base) * 1000 > audio_clock)
{
    // 视频比音频快了，等几毫秒
    Sleep(diff_ms);
}
else if (diff_ms < -50)
{
    // 视频比音频慢了超过 50ms，直接丢掉这帧
    av_frame_free(&frame);
    continue;
}
```

**但这里有一个取巧的做法：**
如果不做精确的 A/V 同步，让解码线程 sleep 来控制帧率（比如 1000/24ms 出一帧），声音和画面大概对齐也够用。因为人眼对毫秒级的音画不同步不敏感（+/-50ms 以内看不出）。但如果视频帧率不稳定，音画差距会越来越大，还是得做同步。

## 第五步：窗口隐藏 + 防多开 + 资源安全

### 5.1 窗口隐藏

目标：用户看不到窗口，但画面在指定位置显示。

技术方案：利用 D3D11 的特性——只要有 HWND 和交换链，画面就能输出。窗口不需要可见。

具体做法：

**MainWindow 改成作为"不可见容器"：**
- 不设置中央 Widget（删掉 centralWidget）
- 设置窗口大小 1x1（最小尺寸）
- 设置窗口位置到屏幕外（-10000, -10000），但为了 D3D11 输出位置准确，不能这么做
- 正确的做法：**创建一个透明窗口**，位置设在目标位置，尺寸设为目标尺寸，但窗口完全透明

```
// MainWindow 构造函数
setAttribute(Qt::WA_TranslucentBackground);  // 透明背景
setStyleSheet("background: transparent;");
setWindowFlags(Qt::FramelessWindowHint | Qt::WindowStaysOnBottomHint | Qt::Tool);
setGeometry(x, y, w, h);
show();  // 要 show，但不显示任何内容
```

但这种做法的局限：透明窗口还是会在任务管理器里看到一个窗口句柄。

**更彻底的隐藏方案：**
完全不创建 Qt 窗口，直接用 Windows API 创建一个"消息窗口"。

```
// 在 FFmpegCore 里或者一个单独的类里
HWND CreateHiddenWindow()
{
    // 注册一个窗口类
    WNDCLASSEX wc = {0};
    wc.cbSize = sizeof(WNDCLASSEX);
    wc.lpfnWndProc = DefWindowProc;
    wc.hInstance = GetModuleHandle(nullptr);
    wc.lpszClassName = L"VideoRenderWindow";
    RegisterClassEx(&wc);

    // 创建窗口
    HWND hwnd = CreateWindowEx(
        WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW,
        L"VideoRenderWindow", L"",
        WS_POPUP,
        x, y, w, h,
        nullptr, nullptr, GetModuleHandle(nullptr), nullptr
    );

    // 设置透明度为 255（完全不透明内容区域）
    SetLayeredWindowAttributes(hwnd, RGB(0,0,0), 0, LWA_COLORKEY);

    // 不显示窗口（不调用 ShowWindow）
    // 但交换链依然能 Present

    return hwnd;
}
```

但这样做要和 Qt 的事件循环协调，稍微麻烦一点。第一步先用 Qt 的透明窗口方案，最后再改也不迟。

### 5.2 防多开

用 QLockFile：

if (!lockFile.tryLock(100))

### 5.3 资源安全和崩溃防护

**正常的资源释放：**

在 FFmpegCore::Close() 里：
1. 设置 playing_ = false，通知解码线程退出
2. join 等待解码线程结束
3. 释放音频相关（QAudioSink::stop()）
4. avcodec_free_context(&codec_ctx_)
5. avformat_close_input(&fmt_ctx_)
6. 释放 D3D11 设备、交换链
7. 等等

**崩溃防护：**

FFmpeg 是不安全的库，一个损坏的视频文件可能让 av_read_frame 崩溃。为了保险：

```
// 在 main.cpp 里
#include <windows.h>
LONG WINAPI UnhandledExceptionHandler(EXCEPTION_POINTERS*)
{
    // 记录崩溃日志
    // 可以在这里写一个 crash dump
    return EXCEPTION_EXECUTE_HANDLER;
}

// main 函数开头
SetUnhandledExceptionFilter(UnhandledExceptionHandler);
```

可以保住底，至少不会弹出 Windows 的错误对话框。
