# 8k30帧

## 一、解决了什么问题

上一个版本的 CPU 回退模式虽然能跑，但 8K 视频用 `sws_scale` 做 CPU 颜色转换，一帧耗费几十毫秒，画面一卡一卡。这个版本解决了两个核心问题：

### 1. 从"CPU 颜色转换"升级到"GPU 着色器渲染"

原来的流程：
```
GPU 解码 → av_hwframe_transfer_data（GPU→CPU 下载）
→ sws_scale（CPU 做 YUV→RGB，大量开销）
→ QImage（CPU 内存）
→ emit 到主线程 → QLabel 显示
```

现在的流程：
```
GPU 解码 → av_hwframe_transfer_data（GPU→CPU 下载 YUV）
→ 逐行 Map/Upload Y 和 UV 到 GPU 纹理（CPU 只搬运不转换）
→ HLSL Shader 做 YUV→RGB（GPU 计算）
→ Present 上屏
```

核心区别：**去掉了 sws_scale 的 CPU 颜色转换，改为 GPU 着色器来做。** 虽然绕不开一次 GPU→CPU 下载 + CPU→GPU 上传，但省掉了最耗时的 YUV→RGB 转换。

### 2. 解决了 NV12 SRV 创建失败的问题

之前尝试直接在解码器的 NV12 纹理数组上创建 Shader Resource View，但你的显卡/驱动不支持 `DXGI_FORMAT_NV12` 格式的 SRV。

**最终方案：创建两张独立的 DYNAMIC 纹理。**

| 纹理                  | 格式       | 尺寸       | 用途             |
| --------------------- | ---------- | ---------- | ---------------- |
| `staging_y_texture_`  | R8_UNORM   | 跟视频一样 | 存放 Y 亮度平面  |
| `staging_uv_texture_` | R8G8_UNORM | 宽高各一半 | 存放 UV 色度平面 |

每帧通过 `Map/Unmap` + 逐行 `memcpy` 把 Y 和 UV 分别上传到这两张纹理。`R8_UNORM` 和 `R8G8_UNORM` 是所有显卡都支持的标准 SRV 格式，不会再创建失败。

### 3. 修复了解码提前结束的 Bug

原来的 `ReadFrame` 在收到 `av_read_frame` 返回的 EOF 后直接退出，没有 flush 解码器内部缓存的帧。问题出在硬解时解码器有自己的 surface pool（ArraySize=20），150 帧后 pool 满了，`avcodec_send_packet` 返回 `EAGAIN`，但代码直接 `continue` 跳过了这个包，导致大量包永久丢失。

**修复方案：**
- 把 `avcodec_receive_frame` 移到前面，先尝试收帧腾出解码器队列空间
- 当 `av_read_frame` 返回 EOF 后，发送 nullptr 包给解码器 flush
- flush 阶段用 while 循环把缓存的帧全部吐出来
- 将 flush 阶段的 `EAGAIN` 也统一视为 `AVERROR_EOF`

修复后从 150 帧（2.5 秒）提升到 4489 帧（完整播放）。数据吻合：149 秒 × 30fps ≈ 4470 帧。

### 4. 动态帧率控制

`DecodeLoop` 里不再写死 `target_frame_delay_ms = 33`，改为从 `FFmpegDecoder` 读取视频流的 `avg_frame_rate` 动态计算。30fps 的视频自动用 33ms，60fps 的视频自动用 16ms。

### 5. Present 垂直同步

`swapchain_->Present(0, 0)` 改为 `Present(1, 0)`，第一个参数 1 表示等待垂直同步，消除画面撕裂。

## 二、目前的渲染管线

```
GPU 解码（D3D11VA 硬解）
    ↓ AVFrame（AV_PIX_FMT_D3D11，格式 170）
av_hwframe_transfer_data（GPU 显存 → CPU 内存）
    ↓ 得到 AVFrame，Y 在 data[0]，UV 在 data[1]
Map(DYNAMIC texture, WRITE_DISCARD)
    ↓ 逐行 memcpy 上传 Y 平面到 staging_y_texture_
Map(DYNAMIC texture, WRITE_DISCARD)
    ↓ 逐行 memcpy 上传 UV 平面到 staging_uv_texture_
绑定两个 SRV（texY + texUV）到着色器
    ↓ HLSL VS + PS 做全屏三角形 NV12→RGB 转换
Present(1, 0) 上屏
```

## 三、当前的性能特征

| 项目       | 情况                                                         |
| ---------- | ------------------------------------------------------------ |
| 8K 30fps   | 能播，帧率大约 ~15fps，比纯 CPU 好                           |
| 瓶颈       | `av_hwframe_transfer_data`（GPU→CPU 8K NV12 ~5ms）+ 逐行 memcpy（8K Y + UV ~5ms） |
| CPU 占用   | 约 15-20%（主要是 memcpy 搬运开销）                          |
| GPU 占用   | 有负载（解码 + 着色器渲染）                                  |
| 下一步优化 | 找到无需 GPU→CPU→GPU 来回搬运的方法                          |

## 四、使用方式不变

main.cpp 里用法不变，硬解 + GPU 渲染是自动的。如果硬件不支持，自动回退到 CPU 路径。
