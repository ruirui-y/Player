```
解码阶段 ──────────────────────────────────────────────→  渲染阶段 ──────────────→

文件 → [解封装] → [解码] → [下载到CPU] → [上传到GPU] → [着色器转换] → [Present上屏]
```

### 阶段一：图片从哪来？

FFmpeg 打开视频文件，调用硬解解码器（D3D11VA），每调用一次 `ReadFrame` 就解出一帧。

| 位置       | 细节                                                         |
| :--------- | :----------------------------------------------------------- |
| **文件**   | `Core/FFmpegDecoder.cpp`                                     |
| **函数**   | `FFmpegDecoder::ReadFrame(AVFrame* frame)`                   |
| **做的事** | 把 H.264/H.265 压缩包 → 解码成一张完整的 NV12 图像           |
| **输出**   | `AVFrame`，格式为 `AV_PIX_FMT_D3D11`（硬解）或 `AV_PIX_FMT_YUV420P`（软解） |

#### ReadFrame 内部的三阶段流程

**先理解新 API 的设计思想：** 投原料（`send_packet`）和收成品（`receive_frame`）是解耦的，比例不是 1:1。一个 I B B P 的 GOP 可能投 4 个包才收出第 1 帧（因为 B 帧依赖后面的 P 帧）。

```
ReadFrame 进入
    │
    ├─ 第①步：先试收帧
    │  avcodec_receive_frame(ctx, frame)
    │  → 解码器内部可能有缓存帧（B 帧重排序等）
    │  → 成功则直接 return 0（不用读包）
    │
    ├─ 第②步：EAGAIN → 读包 + 喂解码器
    │  while (ret == EAGAIN)          ← "不够，再喂点"
    │  {
    │      av_read_frame(fmt, pkt)        ← 从 MP4 文件里读一个压缩包
    │      │
    │      ├─ 是视频包 → avcodec_send_packet(ctx, pkt)  ← 喂给 GPU 硬件解码
    │      │               ↓
    │      │       avcodec_receive_frame(ctx, frame)
    │      │       → ==0 则 return 0（成功收帧）
    │      │       → EAGAIN 继续读下一个包
    │      │
    │      └─ 非视频包（音频/字幕）→ 丢弃，继续
    │  }
    │
    └─ 第③步：Flush 收尾（文件读完了）
       avcodec_send_packet(ctx, nullptr)  ← flush 命令
       while (true)
       {
           ret = avcodec_receive_frame(ctx, frame)
           → ==0 则 return 0（吐出缓存帧）
           → 否则 return AVERROR_EOF（全部解完）
       }
```

#### 异步解码的本质

**你的 DecodeLoop 看起来是同步的——"收一帧 → 渲染一帧 → 再收一帧"。但实际上 GPU 后台可能有多个帧同时在解码。**

```
时间轴 →
                              GPU 硬件解码器
                              │
CPU 线程（DecodeLoop）         │
│                              │
├─ send_packet(帧1) ──────────┤──► 同步：包塞入队列 ✅
│  receive_frame → EAGAIN     │  GPU 正在解帧1（还没解完）
│                              │
├─ send_packet(帧2) ──────────┤──► 同步：包塞入队列 ✅
│  receive_frame → EAGAIN     │  GPU 同时解帧1和帧2
│                              │
├─ receive_frame → OK! 帧1    │  ← 帧1先解完了！
└─ Render(帧1)                 │
```

**三个关键事实：**

| 事实                         | 说明                                                         |
| :--------------------------- | :----------------------------------------------------------- |
| **send_packet 是同步入队**   | 把压缩包拷贝到解码器内部的 CPU 队列里，塞进去就返回。返回值只代表"塞没塞进去"，不代表"解没解完" |
| **GPU 异步消费队列**         | GPU 从队列里取包去解码，这个过程不阻塞 CPU 线程              |
| **receive_frame 是同步收帧** | 从"已解完"队列里取一帧，有就给你，没有就 EAGAIN              |

**你的 while 循环本质上就是在做"一边喂、一边收、谁先解完拿谁"。**

```
send(帧1) → 收不到 → send(帧2) → 收不到 → send(帧3) → 收到了！（可能是帧1）
```

发送顺序和完成顺序不一定一致，因为 GPU 同时在处理多帧。这就是异步的本质。

### 为什么需要 surface pool（纹理池）

因为有异步，所以 GPU 那边可能同时有几帧在解码流水线上。如果只有 1 张纹理：

```
send_packet(帧1) → GPU 往纹理 A 写
send_packet(帧2) → GPU 也往纹理 A 写 → 帧1 的数据被覆盖了 ❌
```

所以需要一个池子，每次 `send_packet` 时从池子里取一个空闲的抽屉让 GPU 写：

```
send_packet(帧1) → pool[0] 被 GPU 写 ← 空闲抽屉
send_packet(帧2) → pool[1] 被 GPU 写 ← 另一个空闲抽屉
send_packet(帧3) → pool[2] 被 GPU 写
receive_frame    → pool[0] 写完了！返回 AVFrame 指向 pool[0]
send_packet(帧4) → pool[0] 空闲了，可以给帧4 用
```

**pool 是 GPU 异步解码的必要基础设施。**

#### 解码后的帧在哪里？

解出来的帧在哪？**取决于解码模式：**

| 解码模式     | 帧的位置                                                     | frame->format            |
| :----------- | :----------------------------------------------------------- | :----------------------- |
| D3D11VA 硬解 | **GPU 显存**中的 `ID3D11Texture2D`（pool 里的某个抽屉），格式是 NV12 | `AV_PIX_FMT_D3D11` (170) |
| 软件解码     | **CPU 内存**中的 `data[0]`=Y, `data[1]`=UV                   | `AV_PIX_FMT_YUV420P` 等  |

**但硬解情况下，AVFrame 的 data[0] 不是 CPU 内存指针，而是 D3D11VA 内部结构体的指针：**

```
AVFrame                        ID3D11Texture2D (ArraySize=20)
┌───────────────────┐          ┌────┬────┬────┬────┬────┬────┐
│ format: D3D11     │          │  0 │  1 │  2 │  3 │  4 │... │
│ data[0] ──────────┼──────►   │    │    │    │帧  │    │    │
│ 指向 pool[3]      │           │    │    │    │ 这 │    │    │
│                   │          │    │    │    │ 里 │    │    │
│ pts / width /     │          │    │    │    │ !  │    │    │
│ height ...        │          └────┴────┴────┴────┴────┴────┘
└───────────────────┘
```

NV12 的结构：

- **Y 平面**：宽×高，每个像素 1 字节，存亮度
- **UV 平面**：宽/2 × 高/2，每两个字节存一组 UV，存颜色

### 阶段二：渲染入口 — 分派到不同渲染路径

| 位置       | 细节                                    |
| :--------- | :-------------------------------------- |
| **文件**   | `Core/VideoRenderer.cpp`                |
| **函数**   | `VideoRenderer::Render(AVFrame* frame)` |
| **做的事** | 根据 `frame->format` 判断走哪条渲染路径 |

```
Render(frame)
    │
    ├─ fmt == AV_PIX_FMT_D3D11 AND 着色器就绪
    │  → RenderHardware(frame)    ← GPU 双纹理着色器渲染（当前正跑的路径）
    │
    ├─ fmt == AV_PIX_FMT_D3D11（但着色器不可用）
    │  → av_hwframe_transfer_data() → RenderSoftware()
    │                                ← CPU 回退路径
    │
    └─ fmt == 其他软解格式
       → RenderSoftware(frame)     ← 纯 CPU 软渲染路径
```

#### 路径一的条件拆解

```cpp
if (fmt == AV_PIX_FMT_D3D11 && swapchain_ && pixel_shader_ && srv_y_)
```

每个条件分别保护什么：

| 条件                      | 在保护什么                                      |
| :------------------------ | :---------------------------------------------- |
| `fmt == AV_PIX_FMT_D3D11` | 这一帧是 GPU 硬解帧（不是软解帧）               |
| `swapchain_`              | 交换链创建成功了（有地方 Present）              |
| `pixel_shader_`           | 像素着色器编译成功了（能算 NV12→RGB）           |
| `srv_y_`                  | Y 平面的 SRV 创建成功了（着色器能读到亮度数据） |

**为什么不检查 `vertex_shader_`？** 因为它和 `pixel_shader_` 在同一个 `InitShaders()` 里一起创建，一个失败整个函数就返回 false，所以 `pixel_shader_` 不为 null 就等价于 `vertex_shader_` 也不为 null。

**为什么不检查 `srv_uv_`？** 同理，它和 `srv_y_` 在同一个 `CreateShaderResourceViews()` 里一起创建。

**本质上是"用最后一个里程碑指针代表整条创建链"的防御性编程习惯。**

#### 什么是"渲染管线"？

**GPU 渲染管线 = 显卡内部的一条固定加工流水线。**

```
输入（顶点数据）→ 顶点着色器 → 光栅化 → 像素着色器 → 输出到屏幕
```

在播放器上下文里，就是 Draw(3,0) 触发的那条流水线：

```
顶点着色器 VS → 光栅化 → 像素着色器 PS（NV12→RGB）→ Present
```

#### 路径二的注释"GPU 管线不可用"是什么意思？

完整翻译过来是：

> **"帧虽然是 GPU 硬解出来的（fmt == 170），但路径一的那条 GPU 渲染流水线（交换链 / 着色器 / SRV）没有完全就绪，无法走纯 GPU 渲染。所以降级：先把帧从 GPU 显存下载到 CPU 内存，再用 sws_scale 做 YUV→RGB 转换。"**

这里的"管线不可用" ≠ UE 引擎里说的"改渲染管线"。

| 概念     | 你的播放器里的"渲染管线"        | UE 引擎里的"渲染管线"                      |
| :------- | :------------------------------ | :----------------------------------------- |
| 含义     | 单次 Draw 调用的 GPU 固定流水线 | 整个引擎组织每一帧渲染的多层架构           |
| 包含     | VS → 光栅化 → PS → Present      | 几十个 Pass（深度、光照、阴影、后处理...） |
| 抽象层级 | **底层**（显卡硬件规格）        | **高层**（引擎渲染架构）                   |
| "改管线" | 改一个 HLSL 着色器              | 前向渲染↔延迟渲染、加自定义 Pass           |

### 阶段三：GPU→CPU 下载

| 位置       | 细节                                     |
| :--------- | :--------------------------------------- |
| **文件**   | `Core/VideoRenderer.cpp`                 |
| **函数**   | `VideoRenderer::RenderHardware()` 开头   |
| **做的事** | 把 GPU 显存中的 NV12 纹理下载到 CPU 内存 |

```
解码器的 NV12 纹理（GPU 显存，不支持 SRV）
    ↓ av_hwframe_transfer_data（GPU→CPU 下载）
CPU 内存中的 AVFrame（data[0]=Y, data[1]=UV）
```

**对应的代码：**

```cpp
// RenderHardware 内
AVFrame* sw_frame = av_frame_alloc();
int ret = av_hwframe_transfer_data(sw_frame, frame, 0);
//                    ↑ 关键 API
// 做完后：sw_frame->data[0] = CPU 内存中的 Y 平面
//         sw_frame->data[1] = CPU 内存中的 UV 平面
```

**为什么要这一步？** FFmpeg 创建的 GPU 纹理 `BindFlags = D3D11_BIND_DECODER`，没有 `D3D11_BIND_SHADER_RESOURCE`，没法创建 SRV，着色器读不了。必须先下载到 CPU 内存，拆成 R8 和 R8G8 再重新上传到 GPU。

### 阶段四：CPU→GPU 逐行上传 — 对应"拆解五：绕行方案"

| 位置       | 细节                                                      |
| :--------- | :-------------------------------------------------------- |
| **文件**   | `Core/VideoRenderer.cpp`                                  |
| **函数**   | `VideoRenderer::RenderHardware()` 中间                    |
| **做的事** | 把 CPU 内存中的 Y 和 UV 逐行 memcpy 到两张独立的 GPU 纹理 |

```cpp
// Y 平面上传（R8_UNORM）
d3d11_ctx_->Map(staging_y_texture_, 0, D3D11_MAP_WRITE_DISCARD, 0, &mapped);
for (int row = 0; row < y_height; row++)
    memcpy(mapped_row_ptr, sw_frame->data[0] + row * linesize[0], width);
d3d11_ctx_->Unmap(staging_y_texture_, 0);

// UV 平面上传（R8G8_UNORM）
d3d11_ctx_->Map(staging_uv_texture_, 0, D3D11_MAP_WRITE_DISCARD, 0, &mapped);
for (int row = 0; row < uv_height; row++)
    memcpy(mapped_row_ptr, sw_frame->data[1] + row * linesize[1], uv_width_bytes);
d3d11_ctx_->Unmap(staging_uv_texture_, 0);
```

**为什么拆成两张纹理？**

| 尝试                             | 结果            | 原因                                                         |
| :------------------------------- | :-------------- | :----------------------------------------------------------- |
| 直接在解码器 NV12 纹理上创建 SRV | ❌ 显卡不支持    | FFmpeg 创建的纹理 `BindFlags=D3D11_BIND_DECODER`，没有 `SHADER_RESOURCE` |
| 自己创建 NV12 纹理再创建 SRV     | ❌ E_INVALIDARG  | NV12 是 planar 格式，D3D11 有额外约束                        |
| **拆成 R8 + R8G8 两张纹理**      | **✅ 100% 成功** | 单通道/双通道格式没有任何特殊约束                            |

### 阶段五：SRV — 对应"拆解四：去哪找图片？"

| 位置       | 细节                                           |
| :--------- | :--------------------------------------------- |
| **文件**   | `Core/VideoRenderer.cpp`                       |
| **函数**   | `VideoRenderer::CreateShaderResourceViews()`   |
| **做的事** | 为 Y 和 UV 纹理创建 SRV（一次性，不每帧重建）  |
| **本质**   | 给着色器一份"说明书"：纹理在哪、什么格式、几维 |

```cpp
// Y 平面 SRV：R8_UNORM，单通道亮度
srv_desc.Format = DXGI_FORMAT_R8_UNORM;
device->CreateShaderResourceView(staging_y_texture_, &srv_desc, &srv_y_);

// UV 平面 SRV：R8G8_UNORM，双通道色度
srv_desc.Format = DXGI_FORMAT_R8G8_UNORM;
device->CreateShaderResourceView(staging_uv_texture_, &srv_desc, &srv_uv_);
```

**SRV 的生命周期：** `CreateSwapChain` 时创建一次 → 每帧复用 → 关闭时释放。不需要每帧重建。

### 阶段六：RTV + 交换链 — 对应"拆解二：往哪绘制？"

| 位置       | 细节                                                         |
| :--------- | :----------------------------------------------------------- |
| **文件**   | `Core/VideoRenderer.cpp`                                     |
| **函数**   | `VideoRenderer::CreateD3D11SwapChain()`                      |
| **做的事** | 创建交换链（管理前后缓冲）+ 创建 RTV（给后缓冲贴"可以画"的标签） |

```
CreateD3D11SwapChain
    ├─ IDXGIFactory::CreateSwapChain(device, &scd, &swapchain_)
    │   → 内部创建两个 ID3D11Texture2D（前缓冲 + 后缓冲）
    │   → OutputWindow = hwnd_（绑定到你的窗口）

```

**关键概念：**
```
交换链                   后缓冲（ID3D11Texture2D）   RTV
┌─────────────────┐     ┌──────────────────┐      ┌──────────────┐

└─────────────────┘     └──────────────────┘      └──────────────┘
                              │
                              ▼
                    OMSetRenderTargets(1, &rtv_, nullptr)
                    → 告诉 GPU：PS 算出的 RGB 写到这张纹理里
```

### 阶段七：着色器 + Draw — 对应"拆解三：怎么绘制？"

| 位置           | 细节                                                         |
| :------------- | :----------------------------------------------------------- |
| **文件**       | `Core/VideoRenderer.cpp`                                     |
| **函数**       | `VideoRenderer::RenderHardware()` 后半段                     |
| **着色器代码** | 内嵌在 `shader_code` 字符串中的 HLSL                         |
| **编译**       | `VideoRenderer::InitShaders()` — 在 CreateSwapChain 时一次编译 |

**每帧渲染时的完整调用：**

```cpp
void VideoRenderer::RenderHardware(AVFrame* frame)
{
    // ① 绑定渲染目标（告诉 PS 把结果画到后缓冲）
    d3d11_ctx_->OMSetRenderTargets(1, &rtv_, nullptr);

    // ② 设置视口（画面在窗口里的位置和大小）
    D3D11_VIEWPORT vp = {0, 0, width, height, 0, 1};
    d3d11_ctx_->RSSetViewports(1, &vp);

    // ③ 装配着色器
    d3d11_ctx_->VSSetShader(vertex_shader_, nullptr, 0);   // 顶点着色器
    d3d11_ctx_->PSSetShader(pixel_shader_, nullptr, 0);     // 像素着色器
    d3d11_ctx_->PSSetShaderResources(0, 2, {srv_y_, srv_uv_}); // 绑定 Y/UV SRV
    d3d11_ctx_->PSSetSamplers(0, 1, &sampler_linear_);     // 绑定采样器

    // ④ 画一个三角形（VS → 光栅化 → PS）
    d3d11_ctx_->Draw(3, 0);

    // ⑤ 上屏
    swapchain_->Present(1, 0);  // 等待垂直同步，消除撕裂
}
```

**GPU 渲染管线在这一帧里做的事：**

```
Draw(3,0)
    │
    ├─ 顶点着色器 VS（每帧执行 3 次，对 3 个顶点）
    │   └─ 用 SV_VertexID 生成 3 个顶点的坐标 + 纹理坐标
    │      顶点0：(-1, 1)  Tex(0,0)
    │      顶点1：( 3, 1)  Tex(2,0)
    │      顶点2：(-1,-3)  Tex(0,2)
    │      → 三个顶点构成一个覆盖全屏的大三角形
    │
    ├─ 光栅化器（GPU 自动完成）
    │   └─ 算出三角形覆盖了哪些像素
    │      对每个像素：插值算出 Tex 坐标
    │
    └─ 像素着色器 PS（对屏幕上的每个像素执行一次）
        └─ 用 Tex 坐标采样两张纹理：
           texY.Sample(samLinear, tex)   → 取亮度 Y
           texUV.Sample(samLinear, tex)  → 取色度 UV
           → NV12 → RGB 转换
           → 输出 RGB 值 → 写到 RTV（后缓冲）
```

### 完整链路总图（带代码位置）

```
文件 (.mp4/.mkv)
    │
    ▼  Core/FFmpegDecoder::ReadFrame
AVPacket (H.264/H.265 压缩包)
    │
    ▼  avcodec_send_packet + avcodec_receive_frame
AVFrame (NV12)  ← 硬解：帧在 GPU 显存，软解：帧在 CPU 内存
    │                                          ↑ 拆解一
    ▼  Core/VideoRenderer::Render
根据 frame->format 判断路径
    │
    ├─ 硬解路径（当前正跑的）
    │   Core/VideoRenderer::RenderHardware
    │   │
    │   ├─ ① av_hwframe_transfer_data    → GPU显存→CPU内存
    │   │                                      ↑ 绕行方案
    │   ├─ ② Map + memcpy（逐行）         → Y 写到 staging_y_texture_
    │   │                                    UV 写到 staging_uv_texture_
    │   │                                     ↑ 拆解五的解决方案
    │   ├─ ③ PSSetShaderResources(2个SRV)  → 告诉 PS "纹理在这"
    │   │                                     ↑ 拆解四
    │   ├─ ④ OMSetRenderTargets(RTV)       → 告诉 PS "往这画"
    │   │                                     ↑ 拆解二
    │   ├─ ⑤ Draw(3,0)                    → VS → 光栅化 → PS → RGB
    │   │                                     ↑ 拆解三
    │   └─ ⑥ Present(1,0)                 → 交换缓冲 → 显示到窗口
    │
    └─ 软解回退路径
        Core/VideoRenderer::RenderSoftware
        ├─ sws_scale(YUV→RGB)
        ├─ QImage
        ├─ emit SigFrameReady → MainWindow::OnFrameReady
```
